# 松果AI v0.1 LangGraph Tutor Agent 方案与开发计划

## 1. 方案结论

松果AI v0.1 的 AI 学习运行时调整为：

```text
微信小程序
  -> 松果AI后端
    -> LangGraph MathMistakeTutorGraph
      -> 大模型 API
    -> 学习档案 / 错题 / 复习 / 家长报告
```

也就是说：

```text
大模型负责当题推理和自然教学表达。
LangGraph 负责把当前题对话组织成可控 Agent 工作流。
松果AI后端负责长期记忆、结构化沉淀、权限、家长端和成本控制。
DeepTutor 不作为 v0.1 主后端，也不作为 v0.1 必选运行时。
```

M6 的一题一会话 LLM Runner 不废弃，定位调整为 M7 的基础层：

```text
M6：沉淀当前题 messages、Student Context Pack、LearningDeposit。
M7：先用 LangGraph 实现 MathMistakeTutorGraph，编排数学错题的当前题对话、护栏、沉淀和同类题生成。
```

## 2. 为什么改成 LangGraph

当前小程序演示暴露出一个问题：如果状态机和规则写得太重，孩子端会像“固定流程表单”，不像在和 AI 老师对话。

松果AI现在更适合采用：

```text
当前题内：AI Agent 自然对话。
题目结束：结构化沉淀到数据库。
下一题开始：读取摘要和相关历史，重新开启新 Agent 会话。
```

LangGraph 适合这个阶段，原因是：

1. 它可以把一次学习任务建模为有状态工作流，而不是无约束聊天。
2. 它支持节点化编排，便于把上下文构建、模型调用、护栏检查、结构化沉淀拆开。
3. 它支持持久化和可恢复执行，适合小程序刷新、后台切换和会话恢复。
4. 它让后续增加 OCR、RAG、错题检索、家长策略、复习计划等工具更自然。

参考官方文档：

```text
LangGraph Overview: https://docs.langchain.com/oss/python/langgraph/overview
Workflows and Agents: https://docs.langchain.com/oss/python/langgraph/workflows-agents
Durable Execution: https://docs.langchain.com/oss/python/langgraph/durable-execution
```

### 3.1 TutorGraph 流程库

`TutorGraph` 是一类流程，不是一个单一固定流程。不同学习场景可以对应不同 Graph：

```text
MathMistakeTutorGraph：数学错题引导流程。
PhotoQuestionGraph：拍照识题和人工确认流程。
EnglishReadingGraph：英语朗读、ASR、发音反馈流程。
WritingCoachGraph：作文/表达引导和修改建议流程。
ParentReportGraph：家长周报和学习建议生成流程。
ReviewPlanGraph：错题复习推荐和掌握度更新流程。
```

v0.1 只实现一个主流程：

```text
MathMistakeTutorGraph
```

其他 Graph 只记录边界和后续方向，不进入 v0.1 代码开发。

### 3.2 v0.1 主流程：MathMistakeTutorGraph

数学错题主流程如下：

```text
start
  -> input_normalize_node
  -> ocr_or_text_confirm_node
  -> math_problem_parse_node
  -> rule_judge_node
  -> build_context_node
  -> call_tutor_model_node
  -> validate_guardrail_node
  -> repair_or_fallback_node
  -> persist_messages_node
  -> generate_practice_node
  -> deposit_on_end_node
  -> end
```

节点说明：

```text
input_normalize_node：统一处理拍照、文本、语音转文本后的题目输入。
ocr_or_text_confirm_node：图片输入走 OCR；置信度低时请求人工确认。
math_problem_parse_node：结构化题目，识别年级、知识点、题型、已知条件和问题。
rule_judge_node：优先用规则、计算器或题型算法判断能否直接判对错。
build_context_node：读取学生摘要、家长设置和相关历史证据。
call_tutor_model_node：调用大模型生成自然追问、讲解和结构化候选。
validate_guardrail_node：检查 Schema、答案泄露、儿童安全和同类题数量。
repair_or_fallback_node：模型输出不合格时修复一次，失败则本地安全兜底。
persist_messages_node：保存当前题内 user/assistant messages 和调用日志。
generate_practice_node：生成 1-3 道同类题，优先绑定知识点和错因。
deposit_on_end_node：题目结束后写入错题、学习记录、StudentMemory 和家长摘要。
```

## 4. 能力边界

### 4.1 大模型负责

```text
理解当前题目
识别孩子当前回答
生成自然追问
解释关键点
生成同类题
生成家长可读总结草稿
输出结构化学习沉淀候选
```

### 4.2 TutorGraph 负责

```text
组装当前题完整 messages
注入 Student Context Pack
调用 OCR / 判题器 / 知识点库 / 错因库等工具
调用模型
校验输出 Schema
执行答案泄露检查
必要时要求模型修复输出
失败时切换本地 fallback
题目结束时触发 LearningDeposit
```

### 4.3 松果AI后端负责

```text
学生档案
家长绑定
child_id 数据隔离
LearningSession / LearningMessage 持久化
QuestionRecord / MistakeRecord / PracticeRecord
StudentMemory
Daily / Weekly / Monthly Summary
家长报告
模型调用日志
成本和额度
儿童安全审计
```

### 4.4 规则和状态机负责

规则和状态机从“主导教学流程”降级为“护栏和降级能力”：

```text
不再在孩子端展示固定步骤数。
不再由状态机硬编码每一步话术。
不再要求所有题型都先进入规则解析。
```

保留职责：

```text
答案泄露检查
同类题数量限制
输出 Schema 校验
标准错因标签映射
低成本高频题 fallback
模型失败时安全兜底
```

### 4.5 工具和模型层负责

工具和模型层不是单一大模型，而是一组可替换能力：

```text
OCR / Vision：识别题目图片和孩子手写内容。
ASR：后续识别英语朗读和语音提问。
Math Rule Judge：小学数学可规则判定的题型优先本地判。
Calculator：计算题、单位换算、容量比较等优先用确定性计算。
Knowledge Point Library：知识点、题型、年级范围。
Misconception Library：标准错因标签和解释。
LLM Provider：负责自然语言引导、错因解释、同类题生成和家长总结。
Vector Store：后续用于教材、讲义、错题相似检索。
```

### 4.6 规则优先，大模型补位

数学题不要默认全部交给大模型判对错。

推荐顺序：

```text
OCR / 文本输入
  -> 结构化解析
  -> 规则 / 计算器 / 题型算法先判
  -> 判不清楚再请大模型协助结构化或解释
  -> 大模型主要负责引导、表达、错因解释和同类题生成
```

原因：

```text
规则判题更稳定。
简单题不消耗 token。
大模型不适合作为唯一正确性来源。
商业化后必须控制单题成本。
```

### 4.7 LangChain 使用边界

LangChain 不是松果AI的总控制器，也不替代业务后端。

v0.1 只把 LangChain 当作可选组件：

```text
模型适配
工具封装
结构化输出解析
Prompt 模板管理
```

不建议 v0.1 使用 LangChain 高层 Agent 作为主链路。主链路由 LangGraph 明确编排。

### 4.8 DeepTutor 复用边界

DeepTutor 不做 v0.1 主链路，但不等于完全废弃。

如果 DeepTutor 中有可复用资产，应拆成以下形态：

```text
题型分类工具
知识点库资料
讲解模板
错因库
启发式提问模板
年级难度控制规则
可选 DeepTutorProvider
```

禁止继续让小程序或学习 API 直接依赖 DeepTutor 的完整聊天流程。

## 5. MathMistakeTutorGraph 状态

v0.1 建议新增 `MathMistakeTutorGraphState`：

```python
class MathMistakeTutorGraphState(TypedDict, total=False):
    child_id: str
    session_id: str
    grade: int
    question_text: str
    input_type: str
    ocr_result: dict
    problem_analysis: dict
    rule_judge_result: dict
    messages: list[dict[str, str]]
    context_pack: dict
    parent_settings: dict
    tutor_reply: str
    structured_state: dict
    learning_deposit_delta: dict
    practice_items: list[dict]
    guardrail_result: dict
    provider_trace: dict
    should_end_session: bool
```

核心原则：

```text
身份字段以后端状态为准，不能信任模型返回。
messages 只包含当前题会话，不自动跨题继承。
context_pack 只包含摘要和少量相关证据。
rule_judge_result 是确定性判题候选，优先级高于模型自然语言判断。
learning_deposit_delta 是模型候选，落库前必须校验和标准化。
```

## 6. MathMistakeTutorGraph 节点设计

### 6.1 input_normalize_node

输入：

```text
图片
文本
语音转文本结果
```

输出：

```text
input_type
question_text
raw_payload
```

### 6.2 ocr_or_text_confirm_node

职责：

```text
文本输入直接通过。
图片输入调用 OCR / Vision。
置信度低时返回 needs_human_confirm=true。
人工确认后继续后续节点。
```

### 6.3 math_problem_parse_node

职责：

```text
识别题型、知识点、年级范围、已知条件、问题、单位和学生答案。
能规则解析的题型优先规则解析。
解析不完整时请求大模型输出结构化候选。
```

输出：

```text
problem_analysis
```

### 6.4 rule_judge_node

职责：

```text
优先用规则、计算器和题型算法判断答案对错。
能确定结果时写入 rule_judge_result。
不能确定时标记 needs_model_judge=true。
```

规则优先覆盖：

```text
四则计算
有余数除法
限载进一
单位换算
时间计算
人民币计算
周长面积基础题
分数小数基础运算
```

### 6.5 build_context_node

输入：

```text
child_id
session_id
question_text
messages
```

处理：

```text
读取 StudentMemory
读取最近 Daily / Weekly Summary
读取家长设置
选取最多 3 条相关历史证据
生成 Student Context Pack
```

输出：

```text
context_pack
parent_settings
```

### 6.6 call_tutor_model_node

输入：

```text
System Prompt
Student Context Pack
当前题完整 messages
输出 Schema
```

输出：

```text
child_message
structured_state
learning_deposit_delta
practice_items
provider_trace
```

### 6.7 validate_guardrail_node

校验：

```text
JSON 可解析
必须有 child_message
answer_unlocked=false 时不泄露最终答案
practice_items 数量为 0-3
child_message 适合小学生
不能要求孩子提供隐私信息
```

### 6.8 repair_or_fallback_node

触发条件：

```text
模型输出无法解析
答案泄露
儿童安全不合格
模型超时或报错
```

处理策略：

```text
优先要求模型按 Schema 修复一次。
修复失败后使用本地安全 fallback。
fallback 只给下一步提示，不直接给最终答案。
```

### 6.9 persist_messages_node

职责：

```text
保存孩子输入
保存松鼠博士回复
保存 provider_trace
支持刷新恢复当前题 messages
```

### 6.10 generate_practice_node

职责：

```text
根据知识点、错因和题型生成 1-3 道同类题。
优先使用规则模板生成，复杂题再调用大模型。
生成结果必须包含答案和简短解析。
```

### 6.11 deposit_on_end_node

触发条件：

```text
should_end_session=true
孩子完成当前题
家长或系统结束本题
```

职责：

```text
生成 LearningDeposit
更新 QuestionRecord
更新 MistakeRecord
更新 PracticeRecord
更新 StudentMemory
生成 Parent Summary Draft
```

## 7. 模型提示协议

M7 的提示协议不要求模型按固定步数教学，但要求模型遵守护栏：

```text
你是松果AI的松鼠博士，面向小学阶段孩子。
你要像老师一样自然对话，不要像流程表。
你不能默认直接给最终答案。
一次只问一个主要问题。
孩子答对中间步骤时，要明确认可，并自然推进下一步。
孩子答错时，要换成更简单的问题或类比。
当需要给关键点时，可以告诉孩子当前解题关键点，但不要一次性把所有关键点和最终答案都给出。
题目结束时，必须总结方法，并生成 1-3 道同类题。
你必须返回 JSON。
```

结构化输出：

```json
{
  "child_message": "你已经算出总人数了。现在想想：2辆车一共能坐多少人？够不够？",
  "structured_state": {
    "phase": "guided_dialogue",
    "answer_unlocked": false,
    "current_focus": "比较容量是否足够",
    "mastered_points": ["求总人数"],
    "possible_misconception": null,
    "should_end_session": false
  },
  "learning_deposit_delta": {
    "knowledge_point": "限载进一应用题",
    "question_type": "capacity_round_up",
    "evidence": "孩子已经能求总人数，但还在比较车辆容量。",
    "need_review": true
  },
  "practice_items": []
}
```

## 8. 运行时开关

新增统一开关：

```bash
export SONGGUO_AGENT_RUNTIME=langgraph
```

允许值：

```text
langgraph：M7 主运行时，默认执行 MathMistakeTutorGraph。
llm：M6 自定义一题一会话 Runner，作为过渡和 fallback。
kernel：规则/Runtime Kernel 兜底模式。
```

旧开关 `SONGGUO_SESSION_RUNNER` 可保留兼容，但新代码优先读取 `SONGGUO_AGENT_RUNTIME`。

## 11. 与 DeepTutor 的关系

v0.1 不移除 DeepTutor 代码，也不把它当成松果AI业务后端。

新的边界是：

```text
v0.1：DeepTutor 不参与主链路。
v0.2：如果需要 RAG、Quiz、Deep Solve，可作为 TutorGraph 的一个工具或 Provider。
v0.3：DeepTutor 与其他 AI Provider 并存，由 AI 编排层选择。
```

这能避免松果AI被 DeepTutor 的目录结构、接口变化和产品边界绑定。

## 12. 结论

松果AI v0.1 的开发主线更新为：

```text
M1-M5：已形成基础学习闭环和结构化学习资产。
M6：保留一题一会话 messages、Context Pack、LearningDeposit 能力。
M7：用 LangGraph TutorGraph 替换“固定状态机式对话”，形成真正像 AI 老师的当前题 Agent。
```

下一步代码开发应优先执行 M7，而不是继续加重规则状态机。
