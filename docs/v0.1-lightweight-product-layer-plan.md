# 松果AI v0.1 轻量产品层方案

## 1. 新定位

松果AI v0.1 不重新做一个大模型，也不把 DeepTutor 作为第一版强依赖。

v0.1 的产品定位压缩为：

```text
松果AI = 大模型能力 + 学生长期学习档案 + 错题复习闭环 + 家长报告 + 数据隔离
```

大模型负责当次生成：

```text
讲题
分步引导
作文辅导
阅读陪练
同类题生成
总结表达
```

松果AI负责产品层能力：

```text
记录
整理
归档
复习
画像
周报
权限
家长端
成本控制
数据隔离
```

## 2. 为什么要收缩

当前大模型已经能完成大量“当次教学表达”工作。MVP 不应把主要精力放在重新造教学引擎，而应补齐大模型天然缺失的产品层：

1. 稳定保存每个孩子的长期学习历史。
2. 自动整理错题、错因和同类练习。
3. 按周、月、学期形成家长能看懂的报告。
4. 持续追踪同类错因是否改善。
5. 保证多个学生之间的数据隔离。
6. 执行家长设置、答案控制和使用额度。
7. 安排错题复习计划。
8. 控制模型调用成本和失败降级。

因此 v0.1 的验证重点不是“AI 会不会讲题”，而是：

```text
AI 讲完题以后，松果AI能不能把结果沉淀成孩子自己的学习档案。
```

## 3. 推荐架构

v0.1 推荐采用轻量四层：

```text
微信小程序
  ↓
松果AI后端
  ↓
LangGraph MathMistakeTutorGraph
  ↓
工具和模型层
  ↓
大模型 API
```

DeepTutor 在 v0.1 中降级为可选引擎：

```text
V0.1：默认通过 LangGraph MathMistakeTutorGraph 编排数学错题流程，松果AI做业务记录、错题、记忆、周报。
V0.2：需要更强知识库、Quiz、Deep Solve 时，再把 DeepTutor 接成 TutorGraph 的工具或 Provider。
V0.3：DeepTutor 作为可替换 AI Engine 之一，和其他模型引擎并存。
```

## 4. v0.1 最小闭环

v0.1 只验证一条链路：

```text
孩子输入或拍照一道题
→ LangGraph MathMistakeTutorGraph 调用工具和大模型分步讲解
→ 松果AI提取结构化学习结果
→ 写入题目记录、错题记录、练习记录
→ 更新 StudentMemory
→ 生成 1-3 道同类题
→ 家长看到本次反馈和周报草稿
```

第一版不做：

```text
完整 DeepTutor 集成
复杂多租户
老师端
机构端
复杂知识库
完整学习画像
复杂自适应复习算法
完整计费系统
```

保留底层字段和接口 seam，但不作为 v0.1 验收重点。

## 5. 最小数据模型

v0.1 的业务数据以轻量结构为主：

```text
Student
LearningSession
QuestionRecord
MistakeRecord
PracticeRecord
StudentMemory
WeeklyReportDraft
ParentBinding
```

其中最重要的是 `StudentMemory`。它不是大模型自己的 memory，而是松果AI数据库里的结构化学习记忆。

示例：

```json
{
  "student_id": "child_001",
  "grade": 3,
  "weak_points": [
    {
      "subject": "math",
      "topic": "两位数乘一位数",
      "error_reason": "把乘以5当成乘以10",
      "count": 4,
      "last_seen": "2026-05-04"
    }
  ],
  "learning_habits": {
    "hint_dependency": "medium",
    "answer_copying_risk": "low",
    "needs_encouragement": true
  }
}
```

## 6. 大模型上下文注入

2026-05-04 后，v0.1 进一步明确为“一题一会话”：

```text
当前题内的完整 messages 可以每轮提交给大模型。
长期历史只以摘要和相关证据片段注入。
题目结束后，当前会话关闭，结构化结果写回数据库。
```

这里的“完整 messages”只指当前这道题从开始到结束的短会话，不包括孩子所有历史会话。

大模型不直接承担长期记忆。每次调用时，松果AI后端临时注入学生摘要：

```text
你是松鼠博士。
学生：三年级。
最近薄弱点：两位数乘一位数。
常见错因：把 ×5 当成 ×10。
家长设置：不要直接给答案。
本次题目：36 × 5 = ?
请用分步引导方式讲解。
```

这样产品体验上像“AI老师记得孩子”，但实际长期记忆由松果AI数据库控制。

更完整的当前题调用输入应包含：

```text
System Prompt：松鼠博士教学协议、答案控制规则、JSON 输出要求。
Student Context Pack：最近一周薄弱点、错因、家长设置、短期目标。
Current Problem Messages：当前题内完整对话。
Output Schema：child_message、structured_state、learning_deposit_delta、practice_items。
```

详细方案见：

```text

songguo/docs/v0.1-langgraph-tutor-agent-plan.md
```

## 7. 结构化沉淀 Schema

大模型讲完题后，松果AI不能只保存聊天记录，必须沉淀结构化结果：

```json
{
  "subject": "math",
  "grade": 3,
  "knowledge_point": "两位数乘一位数",
  "question_type": "计算题",
  "question_text": "36 × 5 = ?",
  "student_answer": "360",
  "is_correct": false,
  "main_error_reason": "把乘以5当成乘以10",
  "hint_level_used": 2,
  "need_review": true,
  "next_practice": [
    "24 × 5 = ?",
    "42 × 5 = ?",
    "18 × 5 = ?"
  ],
  "parent_summary": "孩子本次主要卡在没有理解乘以5是乘以10的一半。"
}
```

该 Schema 是 v0.1 的技术验证重点。

## 8. 仍然需要轻量控制层

虽然 v0.1 以大模型 API 为主，但不能让大模型完全自由聊天。

松果AI仍需保留轻量控制层：

1. 输出 Schema 校验。
2. 答案泄露检查。
3. 学生数据隔离。
4. 会话事件日志。
5. 失败时本地规则 fallback。
6. 同类题数量限制。
7. 家长端只读取结构化结果，不直接依赖聊天文本。

数学题判对错遵循“规则优先，大模型补位”：

```text
OCR / 文本输入
  -> 题目结构化
  -> 规则 / 计算器 / 题型算法先判
  -> 判不清楚再调用大模型协助
  -> 大模型主要负责引导、解释、同类题和家长总结
```

现有 Runtime Kernel、Teaching Assets 和状态机不删除，但定位从“重教学引擎”调整为“护栏和降级层”：

```text
高频题兜底 + 安全控制 + 结构化校验 + 成本控制 + 模型失败降级
```

推荐保留运行时开关：

```text
SONGGUO_AGENT_RUNTIME=langgraph  # MathMistakeTutorGraph 主运行时
SONGGUO_AGENT_RUNTIME=llm        # M6 一题一会话 Runner 过渡模式
SONGGUO_AGENT_RUNTIME=kernel     # Runtime Kernel 兜底模式
```

## 9. 验证目标

v0.1 轻量方案的最小可验证目标：

1. 完成一次题目引导后，能生成结构化学习沉淀。
2. 同一个孩子重复出现同类错因时，StudentMemory 能累计弱点。
3. 家长端反馈能基于 StudentMemory 和错题记录生成，不只复述聊天记录。
4. DeepTutor 关闭或不可用时，主流程仍可运行。
5. 大模型超时或失败时，本地 fallback 能返回可控提示。

## 10. 工程落点

优先开发：

```text
MathMistakeTutorGraph / 数学错题当前题 Agent
LLMSessionRunner / 一题一会话大模型运行器基础层
SessionContextBuilder / 当前题上下文组装
LearningDeposit / 结构化学习沉淀
StudentMemory 更新和查询
Parent Summary Draft
Math Rule Judge / Calculator
Knowledge Point Library / Misconception Library
大模型 Provider 超时降级
DeepTutor 可选 Provider seam
```

暂不开发：

```text
复杂 RAG 知识库
复杂多 Agent 协作
英语朗读 Graph
作文辅导 Graph
完整家长周报 Graph
复习推荐 Graph
老师端
机构后台
完整商业计费
```

## 11. 结论

松果AI v0.1 的核心不是“再造一个AI老师”，而是：

```text
把每次AI讲题后的结果，沉淀成孩子自己的学习档案。
```

这条路线更轻、更快，也更适合验证家庭订阅价值。
