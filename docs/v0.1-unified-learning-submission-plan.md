# 松果AI v0.1 统一 Learning Submission 方案与开发计划

## 1. 背景

现有 v0.1 已经跑通了“题目输入 -> MathMistakeTutorGraph 引导 -> 同类题 -> LearningDeposit -> 家长反馈”的核心链路，但入口和学习资产模型仍然偏“单次会话”。

新的产品判断是：小程序不应该让孩子区分“单题陪练”“整页作业扫描”或“拍照判题”。孩子只需要进入一个统一入口：开始做题。一次提交可能来自文本、拍照或语音，后端统一识别出这次提交里的所有题目，并统一沉淀为一次 Learning Submission。

## 2. 产品原则

### 2.1 首页入口

首页主入口从“找松鼠博士学习”调整为：

```text
开始做题
```

进入后提供输入方式，而不是学习模式：

```text
拍照
语音
输入
```

孩子不需要选择题目数量或作业形态。系统根据输入结果识别出本次提交里的所有题目。

### 2.2 统一学习提交

不再在产品概念上区分：

```text
题目数量
作业形态
输入来源
判题场景
陪练场景
```

统一抽象为：

```text
LearningSubmission
```

一次 LearningSubmission 的流程：

```text
输入来源 text/photo/voice
-> 识别题目和孩子答案
-> 拆成 1 到 N 个 LearningItem
-> 每道题结构化题型
-> 每道题判题
-> 正确题沉淀掌握证据
-> 错误题沉淀错题、错因和掌握风险
-> 生成错题陪练队列
-> 松鼠博士逐题陪练所有错题
-> 全部错题陪练完成后生成本次总结和家长反馈
```

### 2.3 正确题也必须沉淀

松果AI的学习资产不能只来自错题。正确题也要记录为掌握证据，但不能简单等同于完全掌握。

建议先定义证据类型：

```text
submission_correct：本次提交中答对，证明有一次掌握证据。
independent_correct：无提示独立答对，权重最高。
guided_correct：松鼠博士引导后答对，证明本次学会但需要复习。
wrong_then_correct：先错后对，证明当前可以纠正但不是稳定掌握。
wrong_unresolved：陪练后仍未完成，优先复习。
review_correct：后续复习练习中独立答对，证明掌握度稳定性上升。
```

### 2.4 错题陪练队列

如果一次提交有多个错题，松鼠博士不只讲其中一道，而是按队列逐题陪练。

```text
本次提交 12 道题
-> 8 道正确，沉淀 MasteryEvidence
-> 4 道错误，生成 TutorQueue
-> 第 1 道错题进入 MathMistakeTutorGraph
-> 完成后进入第 2 道
-> 直到 4 道全部完成
-> 生成本次学习总结
```

MathMistakeTutorGraph 继续负责“单道错题如何自然追问、如何防答案泄露、如何生成同类题”。新增的 LearningSubmissionGraph 负责“本次提交有几道题、哪些对错、下一道讲哪题、什么时候结束”。

### 2.5 陪练后的掌握度状态

错题陪练完成后，系统必须更新沉淀记录，但不能直接把该题型标记为完全掌握。

陪练完成只说明：

```text
孩子本次错题已被纠正。
孩子在松鼠博士引导下能完成这道题。
该题型近期需要复习。
```

因此错题陪练完成后的状态应为：

```text
corrected_needs_review
```

后续复习逻辑：

```text
错题陪练完成
-> 记录 wrong_then_correct 或 guided_correct
-> 将题型加入近期复习计划
-> 第 1 次复习练习独立答对，记录 review_correct
-> 第 2 次复习练习独立答对，题型可升级为 mastered
```

v0.1 先用规则实现：

```text
1. 陪练完成后，不设置 mastered。
2. 同一题型最近 1-2 次复习练习独立答对，才设置 mastery_state=mastered。
3. 如果复习中再次答错，回到 needs_review，并记录新的错因。
4. mastery_state 是题型级别状态，不是单道题状态。
```

## 3. 目标架构

```text
微信小程序统一入口
  -> /api/v1/learning/submissions
    -> LearningSubmissionGraph
      -> input_normalize
      -> OCR / ASR / text parse
      -> question_split
      -> item_structuring
      -> judge_all_items
      -> deposit_all_items
      -> build_tutor_queue
      -> run_current_wrong_item
        -> MathMistakeTutorGraph
      -> next_wrong_item_or_finish
      -> build_submission_summary
    -> PostgreSQL 学习资产库
```

### 3.1 Graph 分工

```text
LearningSubmissionGraph
  负责一次学习提交的上层编排。
  处理 1 到 N 道题。
  先沉淀所有题目的判题和掌握证据。
  再组织错题队列陪练。

MathMistakeTutorGraph
  负责单道错题陪练。
  继续使用 LangGraph StateGraph。
  继续复用 DeepSeek / LangChain ChatModel / structured output。
  继续负责自然追问、答案护栏、同类题和单道错题陪练结果沉淀。
```

### 3.2 存储边界

学习记录、掌握度、错题归因、作业提交和家长反馈必须用 PostgreSQL 结构化存储。

RAG 后续只用于：

```text
教学素材
题型说明
同类题模板
讲解模板
教研资产检索
```

RAG 不作为孩子学习记录和掌握度主存储。

## 5. API 设计

### 5.1 创建学习提交

```text
POST /api/v1/learning/submissions
```

请求：

```json
{
  "child_id": "child_001",
  "subject": "math",
  "grade": 3,
  "source_type": "text",
  "raw_text": "4 x 5 = ?\n孩子答案：40",
  "image_refs": [],
  "audio_refs": []
}
```

响应：

```json
{
  "submission_id": "sub_001",
  "status": "needs_confirm",
  "items": [
    {
      "item_id": "item_001",
      "question_text": "4 x 5 = ?",
      "child_answer": "40",
      "judge_result": "wrong",
      "knowledge_point": "two_digit_times_one_digit",
      "misconception_tag": "treated_x5_like_x10"
    }
  ],
  "summary": {
    "item_count": 1,
    "correct_count": 0,
    "wrong_count": 1
  }
}
```

### 5.2 确认识别结果

```text
POST /api/v1/learning/submissions/{submission_id}/confirm
```

用于 OCR / ASR 低置信度或拆题后人工确认。

### 5.3 开始或继续错题陪练

```text
POST /api/v1/learning/submissions/{submission_id}/tutor/next
```

如果有 pending 错题，返回当前错题对应的 MathMistakeTutorGraph 会话。

### 5.4 提交当前错题陪练回答

```text
POST /api/v1/learning/submissions/{submission_id}/tutor/attempt
```

内部转发到对应 `tutor_session_id` 的 MathMistakeTutorGraph。

### 5.5 查询学习提交状态

```text
GET /api/v1/learning/submissions/{submission_id}
```

返回本次所有题、判题结果、陪练进度、掌握证据摘要和家长可读摘要。

### 6.1 首页

首页主按钮：

```text

```

首页次级区域：

```text
我的练习记录
薄弱题型
今日复习
```

### 6.2 输入页

统一输入页包含：

```text
拍照
语音
输入
```

拍照后不要求孩子选择题目数量或作业形态。识别后展示确认页：

```text
我识别到 8 道题
请确认题目和你的答案
```

判题后先展示本次概览：

```text
本次共 12 题
答对 8 题
需要松鼠博士陪练 4 题
```

然后主按钮：

```text
开始讲错题
```

### 6.4 错题陪练页

错题陪练页显示当前队列进度：

```text
第 1 / 4 道错题
```

但不把后端状态机步骤暴露成固定教学步骤。松鼠博士仍以自然语言引导。

```text
5. 陪练完成后写入 corrected_needs_review，不直接标记 mastered。
6. ReviewPlan 优先推荐 wrong_unresolved、wrong_then_correct、corrected_needs_review 和低稳定掌握题型。
7. 复习练习连续 1-2 次独立答对后，才把题型升级为 mastered。
```

验收：

```text
1. 家长能看到“本次 12 题，8 对 4 错，4 道错题已讲完”。
2. 正确题能影响题型掌握度。
3. 错题能继续影响错因和复习计划。
4. 陪练完成后的题型会进入近期复习计划。
5. 陪练完成不会直接把题型标记为 mastered。
6. 同一题型经过 1-2 次复习练习独立答对后，才能标记为 mastered。
7. 不再只靠 WrongQuestion 判断孩子薄弱点。
```

## 8. 推荐实施顺序

短期不建议直接做完整 A4 自动切题和手写答案定位。推荐顺序：

```text
1. P1 首页统一入口。
2. P2 数据模型和 store。
3. P3 文本 intake。
4. P4 批量判题和 MasteryEvidence。
5. P5 LearningSubmissionGraph。
6. P6 submissions API。
7. P7 小程序确认页和错题队列。
8. P8 家长反馈和掌握度。
9. P9 真实评测。
10. 在上述闭环稳定后，再提高 OCR/ASR 自动识别质量。
```

原因：

```text
文本 intake 可以先验证统一提交模型。
OCR/ASR 的准确率问题不应该阻塞学习资产模型。
先做结构化沉淀和错题队列，才能证明松果AI的壁垒不是拍照识别，而是长期学习资产。
```
