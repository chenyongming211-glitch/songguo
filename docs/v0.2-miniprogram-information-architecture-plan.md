# v0.2 小程序信息架构与页面收敛方案

## 1. 背景

当前小程序已经具备“开始做题 -> 提交确认 -> 错题陪练 -> 家长报告 -> 设置诊断”的基本闭环，但页面仍混有演示、调试和产品解释内容：

- 学习首页常驻展示“刷新列表”等开发态动作，和孩子真实使用场景不匹配。
- 首页第一屏同时承担产品介绍、做题入口、孩子切换、会话列表和异常提示，主任务不够聚焦。
- 家长页把“报告生成、报告草稿、学习资产、安全拦截、错题证据”等结构并列展示，家长需要自己判断轻重。
- 设置页暴露 BFF、AI 引擎、LLM、Embeddings、Search 等技术诊断信息，适合开发者，但不适合长期面向家长。

本方案目标是把小程序从“可演示工程页面”收敛为“真机私测可用产品页面”。

## 2. 设计原则

1. 第一屏只展示当前用户要做的事情。
2. 刷新默认自动发生，不把“刷新列表 / 刷新报告”作为常驻主按钮。
3. 技术诊断只在设置页出现，且默认折叠到高级区域。
4. 错误态给用户可执行动作，例如“重试”“去设置”，不提示“本地服务是否启动”这类开发语。
5. 孩子端减少解释和营销文案，家长端直接给结论和行动建议。
6. 开发版可以保留调试入口，但正式版默认隐藏可编辑后端地址和底层模型状态。

## 3. 阶段拆分

### 阶段 1：学习主链路页面收敛

目标：先解决真机打开后的第一感受和主要入口。

范围：

- 学习首页：
  - 保留孩子身份、做题入口、最近练习。
  - 把“拍照做题”作为最大主按钮。
  - 把“语音说题”“手动输入”作为次入口。
  - 移除常驻“刷新列表”按钮。
  - 移除常驻三张产品解释卡，改为有数据时显示最近练习，无数据时显示极简空状态。
  - 网络失败时显示“服务暂时连不上”，提供“重试”和“去设置”。
- 提交确认页：
  - 继续展示识别题目、孩子答案和判题结果。
  - 将按钮文案改成业务动作：`确认并保存`、`确认并开始讲错题`。
  - 题型、来源等作为辅助标签，不做主视觉。
- 陪练页：
  - 保留题目卡和对话输入。
  - 减少“学习状态已恢复”“已生成下一步提示”等系统态文案的视觉权重。

验收：

- 学习首页第一屏没有“刷新列表”。
- 默认加载和下拉刷新仍可工作。
- 服务不可用时能看到明确的“重试 / 去设置”动作。
- 小程序现有测试通过。

### 阶段 2：家长页信息层级重排

目标：家长打开后先看到结论，而不是原始模块堆叠。

状态：已完成第一版。家长页已从直接绑定 `report`、`summaryDraft`、`reviewPlan`、`memory`、`wrongQuestions` 等原始 API 结构，调整为页面专用的四组视图模型：本期结论、行动建议、薄弱点和最近错题。`LearningDeposit` 不再作为家长页主流程读取，避免把内部学习资产沉淀过程暴露给家长。

范围：

- 顶部保留孩子选择和“报告周期”下拉。
- 首屏第一张内容卡改为“本周结论 / 本期结论”，只显示 2 到 3 条：
  - 孩子主要卡点。
  - 主要错因。
  - 下一步怎么练。
- 第二块显示“行动建议”，来自复习计划或报告草稿。
- 第三块显示“薄弱点”，来自长期画像。
- 第四块显示“最近错题”，支持标记已掌握。
- “安全拦截记录”仅在存在安全事件时显示。
- “报告草稿”“学习资产沉淀”等内部过程信息默认不作为家长页主模块。
- 移除常驻“刷新报告”，改为自动加载、周期切换自动加载、下拉刷新和错误态重试。

验收：

- 家长页首屏直接能看到结论或空状态。
- 空安全事件不占用页面空间。
- 报告周期切换仍可触发数据重新加载。

### 阶段 3：设置页开发态与家长态隔离

目标：保留私测调试能力，同时避免长期把技术细节暴露给普通用户。

状态：已完成第一版。设置页普通模式只展示“生产学习服务 / 测试连接”等用户可理解信息，不再直接展示原始后端 URL。高级诊断仅在微信开发者工具运行时展示，展开后才显示后端地址、BFF / AI 引擎链路、微信登录模式和模型状态。

范围：

- 默认显示：
  - 当前服务状态。
  - 当前后端地址。
  - 测试连接。
- 高级诊断折叠显示：
  - BFF / AI 引擎链路。
  - LLM、Embeddings、Search 状态。
  - 可编辑后端地址。
  - 恢复默认值。
- 开发版可通过本地开关展示高级诊断。
- 正式版默认隐藏可编辑后端地址，只保留服务状态说明和联系客服/重试入口。

验收：

- 设置页首屏不再像后端调试面板。
- 私测阶段仍可手动测试 `https://api.songguoxue.com`。
- 开发者工具中仍可临时切换本地地址。

## 4. 不在本轮处理

- 不重新设计品牌视觉和完整 Design System。
- 不新增老师端、机构端或家庭成员管理。
- 不改变后端 API 合同。
- 不解决备案导致的 API 域名连通性问题。
- 不做正式商业化版本的权限和发布流程。

## 5. 当前推荐执行顺序

1. 先做阶段 1，让真机首页不再像调试页。
2. 再做阶段 2，让家长报告从“模块堆叠”变成“结论优先”。
3. 最后做阶段 3，把设置页调试能力收进高级诊断。

如果时间有限，阶段 1 和阶段 2 可以合并成一个小程序体验版；阶段 3 可以等备案接入和真机后端联通后再做。
