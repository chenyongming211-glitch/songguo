# 松果AI v0.1 技术实施计划

## 1. 计划定位

本文档把《松果AI PRD v0.1：MVP 核心闭环验证版》转成工程实施计划。

v0.1 只保留一个版本，内部按 M1-M8 推进：

```text
M1：本地学习闭环
M2：小程序可演示
M3：小范围试用准备
M4：AI 教学体系短期落地
M5：结构化学习沉淀
M6：一题一会话 LLM Runner 基础层
M7：MathMistakeTutorGraph 主运行时
M8：真实模型试用闭环
```

当前最重要的是把 v0.1 从“可演示对话”推进到“可沉淀学习资产”的轻量产品层。

2026-05-04 路线调整：

```text
大模型负责当次讲解、引导、作文、阅读、同类题和总结表达。
松果AI负责长期记录、错题整理、复习计划、学生记忆、家长报告、权限和数据隔离。
DeepTutor 降级为后续可选 AI Engine，不作为 v0.1 强依赖。
```

2026-05-04 追加路线调整：

```text
采用“一题一会话”LLM-first 方案。
当前题内完整 messages 每轮都可以提交给大模型。
长期历史只通过 Student Context Pack 注入摘要和相关证据。
题目结束后，LearningDeposit 写回数据库并更新学生学习档案。
```

2026-05-04 再次追加路线调整：

```text
M7 引入 LangGraph MathMistakeTutorGraph。
v0.1 只实现数学错题 Graph；英语朗读、作文、周报、复习推荐等 Graph 先记录流程，不进入当前开发。
```

## 2. 技术架构

当前 v0.1 采用“松果业务后端 + LangGraph MathMistakeTutorGraph + 工具模型层 + 松果业务记忆层”的轻量结构：

```text

  -> /api/v1/learning/*
  -> /api/v1/parent/*
  -> /api/v1/wechat/*

deeptutor/api/main.py
  -> 挂载 songguo/backend/api/routers/*

songguo/backend/api/routers/*
  -> songguo/backend/services/*
  -> TutorAgentOrchestrator / MathMistakeTutorGraph
  -> SQLiteLearningStore
  -> AIEngineProvider / Tool Providers / 大模型 API
  -> 结构化学习沉淀 / StudentMemory / Parent Summary
```

DeepTutor、Teaching Kernel 和结构化数学网关保留，但定位调整为可选增强层、护栏层和安全兜底层：

```text

  -> LearningSession / LearningEvent
  -> WrongQuestion / PracticeRecord
  -> StudentMemory
  -> SessionFeedback / SummaryDraft

  -> LangGraph MathMistakeTutorGraph
  -> input_normalize_node
  -> ocr_or_text_confirm_node

AI Engine Adapter
  -> Direct LLM Provider

Tool and Model Layer
```

## 3. 技术原则

1. M1 不扩大学科范围，核心验收只看小学数学错题闭环。
2. 小程序不直接调用 DeepTutor 原始 WebSocket 作为生产学习流程。
3. DeepTutor 不进入 v0.1 主链路；后续只能通过可选 Provider、工具接口或教学资产进入 MathMistakeTutorGraph。
4. 当前题内完整 messages 可以提交给大模型，但最终落库状态必须经过后端校验。
5. `answer_unlocked=false` 时，任何输出不得包含最终答案。
6. M1 允许 mock child_id，M3 必须建立 `openid/session_token/child_id` 最小绑定。
7. 图解、动画、提醒只保留 seam，不阻塞 M1。
8. 小学数学自然语言题目不靠规则穷举覆盖；规则、计算器和题型算法优先判对错，大模型负责题目理解补位、关键点提取和自然追问。
9. 大模型必须在合适时机告诉孩子解决关键点，但不能一次性把所有关键点或最终答案告诉孩子；状态机只做护栏、校验和 fallback，不主导孩子端话术。
10. Oppia 只作为教学结构和教研资产模型参考，不作为 v0.1 运行时依赖。
11. DeepTutor 属于可选 AI Engine，不属于 v0.1 必选路径；教学节奏、错因、画像和家长反馈由松果AI维护。
12. 孩子端和家长端不展示内部固定步骤数；前端展示自然对话、当前关注点和完成后的方法总结。
13. v0.1 后续新增 M4，补齐 Runtime Kernel、AIEngineProvider、数学种子库和黄金评测集。
14. v0.1 新增 M5，验证结构化学习沉淀：每次 AI 讲题后必须能落到 QuestionRecord、MistakeRecord、PracticeRecord、StudentMemory 和 Parent Summary Draft。
15. v0.1 新增 M6，落地一题一会话 LLM Runner 基础层：当前题完整 messages 给大模型，跨题长期历史只注入摘要和相关证据。
16. v0.1 新增 M7，落地 LangGraph MathMistakeTutorGraph：先只编排数学错题自然对话、规则判题、护栏、降级、沉淀和同类题生成。
17. LangChain 只作为模型适配、工具封装和结构化输出解析的可选组件，不作为松果AI总控制器。
18. 后续可扩展 PhotoQuestionGraph、EnglishReadingGraph、WritingCoachGraph、ParentReportGraph、ReviewPlanGraph，但不进入 v0.1 主开发范围。
19. v0.1 新增 M8，接入真实 DeepSeek 模型，验证真实 AI 老师体验、真实调用日志和小程序演示链路。
20. API key 只允许保存在本地 `.env`，不得写入 docs、测试和代码。

## 3.1 v0.1 当前主线：轻量产品层

v0.1 当前主线不是继续加重教学引擎，而是验证“大模型讲完后，松果AI能不能沉淀学习资产”。

目标链路：

```text
孩子输入或拍照一道题
-> 大模型或 fallback 生成分步讲解
-> 松果AI生成 LearningDeposit
-> 写入/读取错题、同类题、学习记忆
-> 家长端看到本次反馈和周报草稿
```

`LearningDeposit` 是 v0.1 的最小结构化沉淀视图，包含：

```text
QuestionRecord：题目、学科、年级、知识点、题型
MistakeRecord：学生答案、是否正确、主错因、证据
PracticeRecord：1-3 道同类练习
StudentMemory：当前孩子的薄弱项摘要
ParentSummary：家长可读建议
```

## 3.2 v0.1 增强方向：小学数学题目结构化网关

v0.1 MVP 已经完成计算题演示闭环。下一阶段的数学能力升级不再只做单个题型规则，而是引入“小学数学题目结构化网关”。

详细方案见：

```text
songguo/docs/v0.1-math-structured-teaching-gateway.md
```

目标架构：

```text
大模型理解题目
-> 输出 ProblemAnalysis / SolutionStep / KeyPoint
-> MathMistakeTutorGraph 组织当前题自然对话
-> 规则层校验结构、算术、自洽性和答案泄露
-> 孩子提交尝试
-> 系统判断掌握了哪个关键点
-> 记录错因、关键点事件、错题和家长反馈
```

该增强方向的核心不是让大模型自由回答，而是让大模型先回答：

```text
这道题的解决关键点是什么？
每个关键点应该什么时候告诉孩子？
每个关键点应该用什么适龄提示表达？
```

然后由 MathMistakeTutorGraph 和后端护栏决定如何自然释放，而不是在前端展示固定步骤。

## 3.3 TutorGraph 流程库记录

`TutorGraph` 表示一类学习场景流程。v0.1 只实现数学错题主流程，其他流程先记录，不进入代码开发。

```text
MathMistakeTutorGraph：数学错题引导流程，v0.1 主开发对象。
PhotoQuestionGraph：拍照识题和人工确认流程，后续作为输入前置流程。
EnglishReadingGraph：英语朗读、ASR、发音反馈流程，v0.3 后考虑。
WritingCoachGraph：作文/表达引导和修改建议流程，v0.3 后考虑。
ParentReportGraph：家长周报和学习建议生成流程，MVP 先由 reporting service 生成草稿。
ReviewPlanGraph：错题复习推荐和掌握度更新流程，v0.2 后考虑。
```

v0.1 的 MathMistakeTutorGraph 流程：

```text
start
  -> input_normalize_node
  -> ocr_or_text_confirm_node
  -> math_problem_parse_node
  -> rule_judge_node
  -> build_context_node
  -> call_tutor_model_node
  -> validate_guardrail_node
  -> repair_or_fallback_node
  -> persist_messages_node
  -> generate_practice_node
  -> deposit_on_end_node
  -> end
```

## 8.1 M4：AI 教学体系短期落地

M4 是在已有 v0.1 MVP 基础上补齐 AI 教学体系的短期落地能力。M7 之后，M4 产物主要作为 TutorGraph 的护栏、教研资产和 fallback，不再作为孩子端主对话运行时。

详细计划见：

```text
songguo/docs/02-ai-teaching-short-term-plan.md
```

### 8.1.1 M4-1：Runtime Kernel 边界收敛

目标：

```text
Runtime Kernel 收敛为教学护栏和兜底层，负责答案解锁、学习事件、错因记录和低成本 fallback。
```

任务：

```text
1. 明确 Runtime Kernel 输入输出。
2. 统一 ProblemAnalysis / KeyPoint / AttemptEvaluation / TeachingProgress。
3. 状态机只消费结构化结果，不直接生成孩子端主话术。
4. 每一次关键点推进都写 LearningEvent。
5. answer_unlocked=false 时，输出不得包含最终答案。
6. 未结构化题目显示“动态推进”，不暴露内部固定步骤数。
```

验收：

```text
1. 新建学习会话时能返回 teaching_progress。
2. 结构化题目能显示动态关键点进度。
3. 未结构化题目不显示固定步骤数。
4. 孩子答对某个关键点后，TutorGraph 可以自然推进下一步。
5. 孩子答错时，护栏层不允许直接跳到最终答案。
```

### 8.1.2 M4-2：AIEngineProvider 抽象

目标：

```text
DeepTutorProvider、DeepSeekProvider、OllamaProvider、FallbackProvider 走统一接口。
```

Provider 至少支持：

```text
structure_math_problem(question_text, grade, context) -> ProblemAnalysis
generate_hint(problem_analysis, key_point, student_profile) -> TeachingDraft
generate_explanation(problem_analysis, unlock_context) -> TeachingDraft
generate_similar_practice(problem_analysis, misconception, limit) -> PracticeItems
summarize_session(events, profile_delta) -> SessionFeedback
```

验收：

```text
1. LearningService 不直接依赖 DeepTutor 内部接口。
2. Provider 失败时可以降级到确定性安全草稿。
3. Provider 输出必须经过 Schema 校验和泄露检查。
4. Provider 调用有 request_id、student_id、tenant_id、provider、model、latency、token/cost 记录。
```

### 8.1.3 M4-3：数学 Skill / Misconception 种子库

目标：

```text
落地 30 个小学数学高频 Skill、50 个常见 Misconception 和 ConceptCard 极简模板。
```

要求：

```text
1. Skill 有唯一 id、名称、年级范围、学科、简短定义。
2. Misconception 有唯一 id、名称、解释、证据样例。
3. ConceptCard 不直接替孩子做当前题。
4. ProblemAnalysis 能引用 skill_id 和 misconception_id。
5. 家长反馈能显示错因解释，而不是内部标签。
```

### 8.1.4 M4-4：黄金评测集和评测脚手架


覆盖：

```text
计算题

时间和人民币
图形周长面积
有余数除法
限载进一
分数小数初步
四则混合运算
带干扰条件题目
```

阻断指标：



### 8.1.5 M4-5：受控生成闭环

目标：

```text
大模型输出绑定 Skill、Misconception、KeyPoint 和 ConceptCard，由 TutorGraph 自然表达，由 Runtime Kernel 做泄露检查和 fallback。
```

验收：

```text
1. 孩子端只看到当前对话需要的关键点。
2. 当前关键点提示不能泄露最终答案。
3. 孩子卡住时能回到 ConceptCard 或更简单例题。

```

