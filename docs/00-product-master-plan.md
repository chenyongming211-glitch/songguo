# 松果AI PRD 产品总纲

## 1. 文档定位

本文档定义松果AI的整体产品方向、目标用户、核心价值、产品边界、功能架构、商业模式、DeepTutor 集成边界和版本演进路线。

本文档不是某一个版本的详细开发需求，而是后续 `PRD v0.1`、`PRD v0.2`、`PRD v0.3`、`PRD v1.0` 的上位纲领。

```text
产品总纲：回答松果AI是什么、为谁服务、长期怎么做、如何赚钱。
PRD v0.1：回答 MVP 第一版做什么、如何验证核心闭环。
PRD v0.2：回答家庭多孩子、错题复习、学习画像如何增强。
PRD v0.3：回答小学全科陪练和内容能力如何扩展。
PRD v0.4：回答机构、老师、班级场景如何进入。
PRD v1.0：回答商业化正式版如何形成完整平台。
```

当前阶段最重要的是明确四件事：

```text
1. 松果AI和作业帮、讯飞、小猿、班级小管家、家长通有什么不同。
2. 松果AI的 AI 能力如何形成可收费的学习服务闭环。
3. DeepTutor 应该作为 AI 学习引擎，而不是完整业务后端。
4. 松果AI自己的核心资产是 Teaching Kernel，而不是直接复用某个开源产品的完整业务系统。
```

## 2. 产品基本定义

### 2.1 产品名称

松果AI

### 2.2 一句话定位

松果AI是面向小学阶段学生的 AI 学习陪练小程序。每个学生都有自己的专属 AI 老师，系统基于学生的年级、教材、错题、学习记录和学习习惯，进行分步讲解、错因分析、错题复习、个性化练习和家长周报。

### 2.3 完整定义

松果AI是一个面向小学阶段的多租户 AI 学习陪练平台。

平台支持家庭、学校、机构等不同租户。每个学生可以拥有独立学生账号和逻辑上专属的 AI 老师。学生之间的聊天记录、错题、学习画像、家长周报和 AI 记忆不共享。

松果AI不定位为普通搜题工具，也不定位为班级通知工具，而是定位为：

```text
孩子的专属 AI 学习陪练
家长的学习洞察助手
老师/机构后续可用的个性化辅导工具
```

### 2.4 品牌结构

| 层级 | 名称 | 说明 |
| --- | --- | --- |
| 产品名 | 松果AI | 面向家长和学生的主品牌 |
| AI 老师 | 松鼠博士 | 默认 AI 老师形象 |
| 激励体系 | 松果树 | 孩子的成长和学习激励体系 |
| 学习记录 | 松果成长档案 | 学生长期学习画像和报告 |
| 付费服务 | 松果AI会员 | AI 学习陪练订阅服务 |

品牌寓意：松果代表知识的种子。一颗小松果，慢慢长成大森林；一个小知识点，慢慢长成完整能力。

## 3. 产品愿景、使命与原则

### 3.1 产品愿景

让每个孩子都拥有一个耐心、懂自己、不会生气、会一步一步引导的 AI 学习老师。

让家长不只看到孩子做了多少题，而是看懂孩子为什么不会，以及下一步应该怎么帮。

### 3.2 产品使命

松果AI要解决家庭学习中的三个真实问题：

```text
1. 孩子不会题时，家长没时间或不会讲。
2. 孩子经常重复犯错，但没人持续追踪错因。
3. 家长看到分数和对错，却看不懂孩子真正卡在哪里。
```

### 3.3 核心产品原则

```text
1. 不做答案机器，而做学习陪练。
2. 不直接替孩子完成作业，而是引导孩子自己想出来。
3. 不只记录错题，而是记录错因和复习过程。
4. 不只给家长数据，而是给家长可执行建议。
5. 平台能力可共享，学生数据必须隔离。
6. 基础能力可以免费，AI 个性化学习服务可以收费。
7. 面向儿童的产品，安全和隐私必须前置设计。
```

### 3.4 产品底线

松果AI不能做成：

```text
AI 搜题答案工具
替孩子写作业工具
班级通知打卡工具
强制家长付费的家校平台
大而全课程平台
硬件学习机替代品
```

松果AI应该做成：

```text
AI 分步讲解工具
AI 错因分析工具
AI 错题复习系统
AI 专属学习画像系统
AI 家长周报系统
小学阶段 AI 学习陪练平台
```

## 4. 目标用户与核心场景

### 4.1 核心角色

| 角色 | 说明 | 核心诉求 |
| --- | --- | --- |
| 学生 | 小学阶段孩子 | 不会题有人讲，讲得简单，不被批评 |
| 家长 | 主要付费和决策者 | 知道孩子哪里薄弱，知道怎么帮 |
| 老师 | 后续 B 端用户 | 管理班级错题、布置练习、查看统计 |
| 机构 | 后续 B 端租户 | 提高课后辅导效率，形成家长反馈 |
| 平台运营 | 松果AI内部角色 | 管理知识库、租户、内容安全和模型成本 |

### 4.2 小学阶段用户分层

| 学段 | 年级 | 重点能力 | AI 老师表达风格 |
| --- | --- | --- | --- |
| 小学低年级 | 1-2 年级 | 拼音、识字、口算、看图说话、朗读、学习习惯、完整表达 | 短句、多鼓励、少术语、多图像化、一次一个小任务 |
| 小学中年级 | 3-4 年级 | 应用题、乘除法、分数初步、面积周长、阅读理解、日记作文、英语句型 | 引导读题、拆分步骤、训练表达、培养方法意识 |
| 小学高年级 | 5-6 年级 | 分数小数百分数、复杂应用题、几何初步、说明文阅读、作文结构、小升初衔接 | 强调思路总结、题型归纳、错因复盘、自主学习 |

### 4.3 家长痛点

```text
1. 孩子不会题，家长一讲就急。
2. 家长知道孩子错了，但不知道为什么错。
3. 孩子反复犯同类错误，没人安排复习。
4. 家长没时间每天盯学习。
5. 家长担心 AI 直接给答案，孩子照抄。
6. 家长希望看到清晰、简短、可执行的学习建议。
```

### 4.4 核心使用场景

#### 孩子不会一道题

```text
孩子拍照上传题目
-> AI 识别题目
-> AI 不直接给答案
-> AI 先问孩子怎么想
-> AI 分步提示
-> 孩子回答
-> AI 继续引导
-> 总结方法
-> 生成同类题
-> 记录错因
```

#### 孩子做错题后自动复习

```text
AI 记录错题
-> 判断错因
-> 生成复习计划
-> 今日复习提醒
-> 学生完成同类题
-> 判断是否掌握
-> 更新学习画像
```

#### 家长每周查看学习报告

```text
家长打开周报
-> 看到本周进步点
-> 看到高频卡点
-> 看到主要错因
-> 看到下周计划
-> 获得亲子辅导建议
```

#### 一个家庭多个孩子

```text
一个家长账号
-> 绑定多个学生
-> 每个学生独立 AI 老师
-> 每个学生独立错题本
-> 每个学生独立学习画像
-> 每个学生独立周报
```

## 5. 竞品定位与差异化

### 5.1 与作业帮、小猿类产品的区别

作业帮、小猿等产品强在大题库、拍照搜题、作业批改、题目解析、同步练习和 AI 精准练习。

松果AI不应正面拼题库规模，而应强调：

```text
不直接给答案
分步启发式引导
错因追踪
错题复习计划
学生专属画像
家长可执行周报
```

一句话区别：

```text
作业帮更像“这道题怎么做”。
松果AI更像“这个孩子为什么不会，以及怎么一步一步学会”。
```

### 5.2 与科大讯飞学习机的区别

讯飞强在 AI 学习机硬件、精准学体系、语音技术、学习数据和品牌信任。

松果AI的差异化：

```text
不卖硬件
轻量小程序启动
低门槛试用
家庭多孩子订阅
家长周报和错因复习为核心
```

一句话区别：

```text
讯飞像高端 AI 学习机。
松果AI像手机里随时可用的专属 AI 学习陪练。
```

### 5.3 与班级小管家、家长通类产品的区别

班级小管家、家长通类产品核心是家校沟通、班级通知、作业收发、打卡接龙、成绩通知和老师管理效率。

松果AI不能去抢“班级通知/作业打卡”心智。松果AI要收费，必须收费在 AI 学习服务上：

```text
AI 拍照讲题
AI 错因分析
AI 错题复习
AI 作文辅导
AI 阅读陪练
AI 专属学习画像
AI 家长周报
```

一句话区别：

```text
班级小管家管班级任务。
松果AI陪孩子真正学会。
```

### 5.4 核心差异化

```text
1. 每个学生一个专属 AI 老师体验。
2. 学生之间数据严格隔离。
3. 默认不直接给答案。
4. 每道错题都追踪错因。
5. 错题会自动进入复习计划。
6. AI 会长期形成学习画像。
7. 家长看到的是“为什么不会”和“怎么帮”。
8. 基础使用免费，AI 个性化服务收费。
```

## 6. 产品形态与端设计

第一阶段优先做微信小程序，不优先做 App。

推荐路线：

```text
V0.1：微信小程序 + 自研后端 + Web 管理后台基础能力
V0.2：小程序强化家庭多孩子、错题复习、家长周报
V0.3：根据留存和付费情况决定是否做 App
V1.0：小程序 + App + Web 后台组合
```

先做小程序的原因：

```text
1. 家长天然在微信里。
2. 分享和私域传播更方便。
3. 不需要下载安装。
4. 更适合 MVP 验证。
5. 微信支付链路更短。
6. 可以先验证学习闭环和付费意愿。
```

```text

今日复习
我要练一练
我要写作文
我要读一读
我的松果树
```

```text
拍一拍
说一说

```

### 6.2 家长端核心入口


后台不建议做在小程序里，应使用 Web 后台。后台负责：


App 不是第一阶段必做。如果后续做 App，它应承载更强的深度学习体验：

```text

英语跟读评分

更强摄像头和手写体验
```

## 8. AI 核心能力设计

### 8.1 AI 拍照讲题

目标：让学生拍一道题后，AI 像老师一样一步一步引导，而不是直接给答案。

```text
拍照上传
-> OCR 识别
-> 题目结构化
-> 判断学科/年级/知识点/题型
-> 读取学生画像和最近错题
-> AI 分步提示
-> 学生回答
-> AI 继续引导
-> 总结方法
-> 生成同类题
-> 写入学习记录
```

题目结构化示例：

```json
{
  "subject": "math",
  "grade": 3,
  "topic": "两位数乘一位数",
  "question_type": "计算题",
  "question_text": "36 × 5 = ?",
  "student_answer": "150",
  "difficulty": 2,
  "target": "求乘积"
}
```

### 8.2 AI 错因分析

目标：从“这题错了”升级为“孩子为什么错”。

错因分析应包括主错因、辅助错因、判断证据和后续练习建议。

```json
{
  "main_error_reason": "列式错误",
  "secondary_error_reasons": ["没读懂题", "漏看关键词"],
  "evidence": "学生把每人6颗理解成总共6颗",
  "suggestion": "先训练找已知条件和问题"
}
```

### 8.3 AI 错题复习

目标：让错题从“收藏”变成“直到掌握”。

```text
新增错题
-> 分析错因
-> 生成同类题
-> 安排复习时间
-> 学生完成复习
-> 判断掌握状态
-> 更新学习画像
```

初期复习节奏：

```text
当天：立即练 1-3 道
第 2 天：复习 1 次
第 7 天：混合复习 1 次
第 14 天：检测 1 次
```

掌握状态：

```text
未掌握
需要帮助
正在练习
基本掌握
熟练掌握
```

### 8.4 AI 作文辅导

原则：不代写，先引导。

```text
不替孩子完成整篇作文
不直接输出完整作业答案
先提问，再示范
先结构，再语言
先孩子表达，再 AI 润色
```

能力包括看图说话、日记辅助、扩句训练、作文提纲、段落修改、病句修改、好词好句建议和作文反馈。

### 8.5 AI 阅读陪练

目标：从“读完”变成“读懂”。

```text
文章导入
-> 分段阅读
-> 生词解释
-> 内容复述
-> 分层提问
-> 主旨概括
-> 完整回答训练
-> 阅读报告
```

分层问题：

```text
事实题：文章写了谁，做了什么？
理解题：为什么这样做？
概括题：这段主要讲什么？
表达题：你有什么感受？
迁移题：生活中有没有类似事情？
```

### 8.6 AI 英语跟读评分

小程序可以负责播放标准音频、录制孩子跟读、上传音频、展示评分结果和保存跟读记录。

后端负责校验 `student_id`、调用语音评测服务、解析评分结果、写入学习记录、更新英语画像和控制调用额度。

英语跟读评分可从 P1 或 P2 开始做，不是 MVP 必须项。

### 8.7 AI 专属学习画像

目标：让松鼠博士越来越懂每个孩子。

画像包括数学画像、语文画像、英语画像、学习习惯画像、情绪与互动偏好、家长设置和老师备注。

画像必须可解释。不要只显示：

```text
读题能力：60分
```

而要显示：

```text
读题能力偏弱：最近5道应用题中，有3道漏看了关键条件。
```

### 8.8 AI 家长周报

周报不是流水账，而是行动建议。

```text
1. 本周学习概况
2. 本周进步点
3. 本周高频卡点
4. 高频错因分析
5. 复习完成情况
6. AI 老师观察
7. 下周学习计划
8. 家长辅导建议
9. 需要关注的问题
```

周报核心价值：

```text
告诉家长孩子为什么不会
告诉家长下周怎么练
告诉家长辅导时该怎么说
```

## 9. 多租户与学生数据隔离

松果AI不是单家庭工具，而是多租户平台。

租户类型：

```text
家庭租户
学校租户
机构租户
老师个人租户
平台直营租户
```

平台层级：

```text
平台：松果AI
  ↓
租户：家庭 / 学校 / 机构
  ↓
学生：每个学生独立学习主体
  ↓
```

## 10. AI 教学引擎长期策略

松果AI长期不应在 Oppia 和 DeepTutor 之间二选一。

推荐方案是：

```text
Oppia 提供教学结构参考
DeepTutor 提供 AI 引擎能力
松果AI自研 Teaching Kernel
```

Oppia 的价值在于教学结构模型，包括：

```text

Story
Skill
Exploration
Card
Interaction
Response
Misconception
Concept Card
```

这些概念适合被松果AI吸收为教研资产库，但不建议把 Oppia 作为运行时教学引擎直接接入小程序。

DeepTutor 的价值在于 AI 工程底座，包括：

```text
RAG
Deep Solve
Quiz
TutorBot
Memory
多模型 Provider
工具调用
```

DeepTutor 适合作为 AI Engine 的核心实现之一，但不能直接控制孩子端教学状态。

松果AI Teaching Kernel 负责：

```text

答案泄露检查
学生画像更新
复习计划

```

Teaching Kernel 不应一次性做成大而全平台。落地时应拆成：


## 14. 成本与模型路由

主要成本：

```text
大模型调用成本
OCR 识别成本

图片/音频存储成本
DeepTutor 部署成本
内容安全审核成本
客服和运营成本
```

成本控制策略：

```text
1. 免费版严格限额。
2. 简单问题使用规则引擎或小模型。
3. 普通题使用中等模型。
4. 复杂题和作文使用强模型。
5. 高频题型模板化。
6. OCR 结果缓存。
7. 同类题生成模板化。
8. 周报异步批量生成。
9. 设置套餐额度。
10. 超额购买加油包。
```

模型路由策略：

```text
口算/简单计算：规则引擎或小模型
普通应用题：中等模型 + 题型模板
复杂应用题：强模型 + DeepTutor Deep Solve
作文修改：强模型
周报生成：批量异步模型
内容安全：专门审核模型或规则
```

成本健康线建议：

```text
单个付费学生月 AI 成本控制在订阅收入的 20%-30% 以内。
```

### 17.7 V0.1 成功标准

V0.1 的成功不以功能数量衡量，而以最小学习闭环是否成立衡量。

```text

```

错因侧：

```text

```


```text

M3 前能估算单学生月 AI 成本
```

### 17.8 核心教学协议

松果AI的 AI 老师不是普通聊天机器人，而是受控教学流程执行者。

V0.1 默认教学协议：

```text
START：接收问题
PARSE：识别题目
CONFIRM：确认题意和识别结果
HINT_1：一级提示
HINT_2：二级提示
HINT_3：错因提示
EXPLAIN：条件满足后完整讲解
CHECK：检查孩子理解
PRACTICE：同类题练习
SUMMARY：本次学习反馈
RECORD：记录错因和错题
END：结束任务
```

模型不能直接推进教学状态。教学状态只能由松果AI业务状态机根据孩子输入、提示等级、尝试次数和安全策略推进。

## 19. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 被当成搜题工具 | 默认启发模式、限制直接答案、讲解后必须追问或出同类题、家长可关闭直接答案 |
| 家长不愿付费 | 基础免费、AI 深度服务收费、强调周报和错题复习价值、先做家庭订阅再做机构 SaaS |
| AI 调用成本过高 | 套餐额度、模型路由、模板化、缓存、异步生成、加油包 |
| 学生数据串租户 | 所有学生数据强制 `tenant_id` 和 `student_id`、API 统一权限中间件、向量库命名空间隔离、Adapter 强制注入身份、审计日志 |
| AI 安全风险 | 输入过滤、输出过滤、儿童安全提示词、敏感场景转家长提醒、内容安全日志、人工复核机制 |
| DeepTutor 耦合风险 | DeepTutor 只作为引擎、自研业务后端、AI 编排层解耦、Adapter 隔离版本变化、业务主数据不依赖 DeepTutor |
