# v0.2 题型路由层规划

## 目标

小程序不让孩子选择题型。后端在 OCR 之后统一执行题型路由，把每道题分到最合适的判题链路：能确定性判分的立即打对错，不能确定性判分的继续交给数学智能体或学科 rubric。

2026-05-17 设计校准后，题型路由层的上游默认应优先消费 `RecognizeEduPaperStructed` 的结构化结果，而不是只依赖 `PaperCut` 的题干文本。`PaperStructed` 提供的 `part_info / subject_list / type / answer_list / element_list` 应成为题型路由的主要证据；`PaperCut` 和 `PaperOcr` 作为结构化失败、题框兜底和文本补强使用。

## 路由范围

| 题型 | 路由标识 | 默认判题链路 | 说明 |
| --- | --- | --- | --- |
| 口算 / 直接算式 | `math_oral_calculation` | 确定性计算 | 包含 `48÷6=?`、整数四则和教育 OCR 口算结果。后续清晰口算页可优先使用 `RecognizeEduOralCalculation`。 |
| 比较符号 | `math_comparison_sign` | 确定性计算 | 拆成多个 `左表达式 ? 右表达式` 子题，答案数量和题目数量一致时才判，避免 OCR 漏答案时误判。 |
| 判断题 | `math_true_false_fact` | 高频事实确定性判断 | 先覆盖小学数学高频事实类判断；未覆盖的判断题进入兜底。 |
| 选择题 | `math_choice` / 细分选择题 | 确定性计算优先 | 包括估算、位数判断、方框数字、直接计算选项。 |
| 填空题 | `math_fill_blank` / 细分填空题 | 确定性计算优先 | 包括积的位数、末尾 0、OCR 噪声答案抽取后的填空。 |
| 应用题 | `math_word_problem` / `math_fill_blank_word_problem` | 简单填空确定性；复杂题走数学智能体 | 简单乘法应用题直接判；自然语言复杂题保留给 `MathProblemStructuringGateway`。 |

## 数据流

```text
Education OCR
-> OCRItemDraft(question_text, child_answer, bbox, action)
-> QuestionTypeRouter
-> ObjectiveJudge / MathGateway / BasicSubjectRubric
-> LearningItem(judge_result, question_type_id, knowledge_point)
-> MasteryEvidence / TutorQueue
```

## 原则

1. 前端仍然只有拍照、语音、输入入口，不暴露题型选择。
2. 题型路由只做分派，不负责生成教学话术。
3. 能精确计算的题型先本地判，减少大模型延迟和费用。
4. OCR 答案数量和题目数量不一致时，不直接判错，交给兜底。
5. 题型路由结果要进入 `question_type_id` 和 `objective_judge`，供家长报告、复习计划和后续评测使用。

## 当前已落地

- 新增 `question_type_routing.py`，统一识别 6 类数学题型。
- 扩展 `objective_judging.py`，支持口算、比较符号、常见判断、选择、填空和简单应用题确定性判分。
- `evaluate_submission_items` 已先执行确定性题型判分，失败后再进入原数学智能体链路。

## 后续补齐

1. 用真实照片继续扩展判断题事实库和比较符号 OCR 修复。
2. 对清晰口算页增加 `RecognizeEduOralCalculation` 自动优先策略。
3. 将 `PaperStructed` 的 `part_info / subject_list / type / answer_list / element_list` 映射进题型路由，减少 raw text 重解析。
4. 为每类题型建立小型黄金集，按题型统计识别率、判题率、误判率和平均耗时。
