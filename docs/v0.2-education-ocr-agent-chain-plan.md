# v0.2 教育 OCR 能力路由与拍照判题整改方案

## 0. 2026-05-17 设计校准结论

当前代码和此前文档还不是完全按本方案设计。当前实现已经接入 `PaperCut / PaperOcr / PaperStructed / OralCalculation / QuestionOcr / Formula` 的 action 映射，并能解析一部分 `PaperStructed` 结果，但默认 `auto` 主链路仍偏向 `RecognizeEduPaperCut`，`RecognizeEduPaperStructed` 更多是可选增强或 A/B 路径。

从本次设计校准开始，产品目标口径调整为：

```text
整页拍照默认优先 RecognizeEduPaperStructed
  -> 拿题型、题区、题干、选项、答案位置和元素结构
  -> 结构化失败或结果不足时兜底 RecognizeEduPaperCut
  -> 文字/答案覆盖不足时补 RecognizeEduPaperOcr
  -> 疑似口算块或口算页再调用 RecognizeEduOralCalculation 直接判对错
  -> 单题复核用 RecognizeEduQuestionOcr / RecognizeEduFormula
  -> 非口算题最终对错由松果自己的题型路由、规则判题、学科 rubric 或智能体完成
```

也就是说，教育 OCR 的主职责是“识别、切题、给结构和坐标”；只有口算判题接口可以直接作为强判题证据。选择、填空、判断、应用题、语文、英语和开放题都必须进入松果自己的判题层。

### 0.1 P0 图像基准原则：先扶正，再识别，再叠框

拍照判题链路必须先解决图像基准问题，否则 OCR 坐标、题框叠加和孩子看到的复核图会持续错位。后续代码实现以如下原则为准：

- 后端收到原始照片后，必须先经过 `OpenCV` 文档检测、透视扶正、内容裁剪、质量检测和压缩增强。
- OCR 输入统一使用 OpenCV 生成的扶正图；原始斜图只保留为审计、问题排查和必要时重试用，不作为默认 OCR 输入。
- 小程序复核页展示服务端返回的扶正预览图 `preview_image_url`，只有服务端没有生成预览图时才退回本地原图。
- 每题 `bbox`、`detected_regions` 和后续叠框坐标都必须以扶正预览图为归一化坐标基准，不能把原图坐标和扶正图坐标混用。
- 质量提示先由后端 OpenCV 输出，例如倾斜已自动扶正、模糊、反光、内容不足、需要重拍等。
- 小程序端实时提示“请放平手机、四角入镜、避免反光”是下一阶段能力，可使用手机传感器和轻量图像检测实现，不依赖大模型，也不阻塞当前 P0。

## 1. 背景修正

当前产品主链路不是“AI 聊天优先”，而是：

```text
拍照 / 语音 / 输入
  -> 生成做题提交 draft
  -> 识别每道题和孩子答案
  -> 在复核页显示题目框、对错和待确认状态
  -> 记录学习证据
  -> 错题进入松鼠博士陪练
```

后续整改不推翻这个方向，而是把拍照判题链路从“固定调用某个 OCR 场景”升级为“按阿里云教育 OCR 能力自动路由”。目标体验是接近小猿 AI 类产品：一页作业拍照后，每道题被框住，每题给出 `正确 / 错误 / 待确认`，错题再进入陪练。

## 2. 目标

### 2.1 产品目标

- 孩子只需要拍照，不选择学科、题型或 OCR 模式。
- 普通多题页要自动拆题，并在原图上显示题目框。
- 每题都要有状态：`correct`、`wrong`、`pending` 或 `fallback_running`。
- 口算题尽可能走教育 OCR 的口算判题能力，快速给出对错。
- 非口算题由 OCR 提供题目、答案和结构化证据，再交给本地规则或学科智能体判题。
- 低置信度题不强判，进入待确认或异步复核。
- 错题、待确认题和复核失败原因都要进入学习记录，便于家长端和后续评测复盘。

### 2.2 技术目标

- 新增 `EducationOcrRouter`，负责根据图片类型、OCR 场景质量和成本策略选择阿里云教育 OCR 能力。
- 新增统一 `EducationOcrItem` 归一化层，把不同 OCR 接口的返回统一成 `items + bbox + child_answer + confidence + source_action`。
- 补齐 `RecognizeEduPaperStructed` 专用解析，不再只把它当普通文本解析。
- 保留 `OpenCV` 质量检测、扶正、压缩和候选框职责，但不默认切图增加 OCR 调用次数。
- 建立 raw OCR 对比脚本和真实照片评测集，用数据决定默认策略。
- 将 OCR 识别、判题、异步复核、陪练拆成可观测的阶段，记录耗时、模型、调用次数、失败原因和成本。

## 3. 阿里云教育 OCR 能力清单

阿里云读光教育场景识别包含多种能力，不能把它当成一个通用 OCR 使用。

| 能力 | 官方定位 | 产品内职责 | 使用边界 |
| --- | --- | --- | --- |
| `RecognizeEduPaperStructed` 精细版结构化切题 | 多学科教辅试卷结构化识别，自动切题并识别全部字段和坐标 | 整页作业默认主入口，优先提取题型、题干、选项、答案位置、题目元素和题区坐标 | 仍然不是通用判题器；结构缺失、合题或漏拆时必须兜底 |
| `RecognizeEduPaperCut` 试卷切题识别 | 整页练习册、试卷或教辅自动切题，输出题目、题干、选项、答案等结构化内容和坐标 | `PaperStructed` 不稳定时的题区兜底，也可用于快速框选和题号排序 | 不能单独承担所有答案抽取和最终判题 |
| `RecognizeEduPaperOcr` 整页试卷识别 | K12 全学科整页内容文字识别，支持印刷体、公式、文字块和配图坐标 | 当结构化/切题结果答案覆盖不足时补全文字和孩子答案；也用于原始全文给学科路由 | 不作为最终默认主入口，因为它不稳定输出每题题框 |
| `RecognizeEduOralCalculation` 口算判题 | 小学口算题识别并给出判断结果，支持加减乘除、混合运算、大小比较等 | 口算页最快路径，直接产生对错证据和题目框 | 不适合应用题、语文、英语、复杂过程题 |
| `RecognizeEduQuestionOcr` 题目识别 | 单题识别并对题目元素打标 | 单题拍照、用户点选某题复核、低置信度题裁剪后复识别 | 不作为整页多题入口 |
| `RecognizeEduFormula` 印刷体数学公式识别 | 印刷体公式识别 | 公式区域局部兜底，提升公式文本质量 | 不负责整页切题和手写答案判分 |

## 4. 目标架构

```text
小程序拍照
  -> /api/v1/learning/submissions/photo-draft
  -> PhotoQualityAnalyzer
     - 解码、尺寸、清晰度、曝光、反光、倾斜、压缩建议
     - 只在必要时提示重拍，不默认切成多张图
  -> EducationOcrRouter
     - 选择 primary_action
     - 判断是否允许 secondary_action
     - 记录 reason / cost_level / expected_output
  -> AliyunEduOCRProvider
     - 调用 OralCalculation / PaperCut / PaperOcr / PaperStructed / QuestionOcr / Formula
  -> EducationOcrNormalizer
     - 统一 raw_text、items、bbox、answer、confidence、warnings
  -> PerItemGrading
     - 口算客观结果
     - 本地规则判题
     - 学科 Tutor Agent / rubric 判题
  -> Submission Review Page
     - 原图题框
     - 每题正确/错误/待确认/复核中
  -> Async Fallback Worker
     - 低置信度题异步复核
     - 单题 QuestionOcr / Formula / 视觉模型兜底
  -> Tutor Queue
     - 错题逐题陪练
     - 学习资产、错因、知识点、家长报告沉淀
```

## 5. OCR 能力路由策略

### 5.1 默认策略

默认策略不是“每张图多接口全跑”，而是“结构化优先，结果不足再补一次”。一张照片的同步主链路原则上控制在 1 次 OCR 调用；只有质量门禁失败或答案覆盖明显不足时才追加 1 次整页兜底。

```text
疑似口算页
  -> RecognizeEduOralCalculation

普通整页作业 / 标准试卷 / 练习册
  -> RecognizeEduPaperStructed
  -> 如果结构缺失、合题、漏题或题区不可用，再补 RecognizeEduPaperCut
  -> 如果题区可用但答案覆盖率不足，再补 RecognizeEduPaperOcr

单题拍照或某题复核
  -> RecognizeEduQuestionOcr

公式局部识别差
  -> RecognizeEduFormula
```

### 5.2 路由计划结构

`EducationOcrRouter` 输出内部计划，不直接生成教学内容：

```json
{
  "primary_action": "RecognizeEduPaperStructed",
  "secondary_actions": ["RecognizeEduPaperCut"],
  "reason": "structured_first_multi_question_homework",
  "expected_output": "structured_question_items",
  "cost_level": "normal",
  "allow_async_fallback": true,
  "subject_hint": "default"
}
```

### 5.3 触发条件

| 条件 | 动作 |
| --- | --- |
| 题目呈密集横式、比较大小、口算页版式 | 优先 `RecognizeEduOralCalculation` |
| 一页多题、练习册、教辅、试卷 | 优先 `RecognizeEduPaperStructed` |
| `PaperStructed` 返回 `part_info / subject_list / element_list / answer_list` 完整 | 直接进入统一 item 归一化和题型路由 |
| `PaperStructed` 合题、漏题、题区不可用或置信度低 | 同图补调 `RecognizeEduPaperCut` |
| `PaperCut` 题框可用，但 `child_answer` 覆盖率低于阈值 | 同图补调 `RecognizeEduPaperOcr` |
| 某题框内文字缺失、答案缺失、置信度低 | 异步裁剪该题后调 `RecognizeEduQuestionOcr` |
| 某题公式区域识别异常 | 异步局部调 `RecognizeEduFormula` |
| OCR 报错、超时、套餐不足或限流 | 返回可解释状态，不强行判题；必要时进入视觉模型兜底 |

## 6. 统一数据模型

无论底层 OCR 接口是什么，后端和小程序只消费统一结构。

```json
{
  "review_id": "photo_review_id",
  "image_path": "...",
  "ocr_plan": {
    "primary_action": "RecognizeEduPaperStructed",
    "secondary_actions": ["RecognizeEduPaperCut"],
    "reason": "structured_first_multi_question_homework"
  },
  "items": [
    {
      "item_index": 1,
      "question_text": "21×50 时，可以先算...",
      "child_answer": "105",
      "work_steps": "",
      "bbox": {"x": 120, "y": 230, "width": 520, "height": 110},
      "ocr_action": "RecognizeEduPaperStructed",
      "ocr_confidence": 0.86,
      "grading_status": "wrong",
      "needs_manual_confirm": false,
      "quality_warnings": []
    }
  ],
  "summary": {
    "item_count": 10,
    "correct_count": 6,
    "wrong_count": 2,
    "pending_count": 2,
    "fallback_running_count": 0
  }
}
```

`bbox` 坐标统一归一化为 0-1000，前端用同一套叠框逻辑渲染。

## 7. 判题职责边界

教育 OCR 不等于陪练智能体，也不应该承担所有最终判题。

| 层级 | 职责 |
| --- | --- |
| 教育 OCR | 看清题目、切题、识别答案、给坐标、口算题给客观结果 |
| 本地规则 | 选择、判断、填空、简单计算等可确定题快速判对错 |
| 学科智能体 | 语文、英语、应用题、开放题、过程题的 rubric 判分、错因和陪练 |
| Tutor Queue | 只把错题和待陪练题送入逐题陪练，不把整页内容变成泛聊 |

口算题可以把 `RecognizeEduOralCalculation` 的结果作为强判题证据，但仍要进入松果自己的学习资产沉淀。语文、英语和开放题只把 OCR 当文本和结构输入，最终反馈由学科 rubric 完成。

## 8. 小程序页面整改

### 8.1 拍照页

- 只强调拍清楚、整页入镜、避免反光。
- 不出现 OCR 模式、学科或题型选择。
- 本地可做简单质量提示：太模糊、过暗、过小、倾斜过大。

### 8.2 识别结果复核页

这是核心页面：

- 顶部显示：共几题、正确几题、需陪练几题、待确认几题。
- 原图上叠加题框和 `✓ / × / ? / 复核中`。
- 点击题框可查看题目文本、孩子答案、识别置信度和修改入口。
- 待确认题允许孩子或家长改题目、改答案，再重新判题。
- 错题一键进入陪练队列。

### 8.3 陪练页

- 只处理错题或家长主动选择的题。
- 页面语义从“聊天”收敛为“错题陪练”。
- 每次陪练结束后写入错因、关键点、复习计划和家长报告证据。

## 9. 异步复核体验

为了接近“几秒钟出结果”，整页不要等待所有低置信度题都复核完成。

```text
T0: 上传照片
T1: 返回题框和初步判题结果
T2: 前端展示已完成题、待确认题、复核中题
T3: 后端异步复核疑难题
T4: 某题复核完成后更新该题状态
```

优先保障首屏：

- 有可用题框先展示题框。
- 可判题先显示 `✓ / ×`。
- 不确定题显示 `待确认` 或 `复核中`。
- 异步复核只处理少数题，避免整页阻塞。

## 10. 配置建议

默认配置建议：

```bash
SONGGUO_PHOTO_OCR_PROVIDER=aliyun_edu
SONGGUO_ALIYUN_EDU_OCR_SCENE=auto
SONGGUO_ALIYUN_EDU_OCR_ROUTER_MODE=auto
SONGGUO_ALIYUN_EDU_OCR_MAX_SECONDARY_ACTIONS=1
SONGGUO_ALIYUN_EDU_OCR_CUT_TYPE=question
SONGGUO_ALIYUN_EDU_OCR_IMAGE_TYPE=photo
SONGGUO_ALIYUN_EDU_OCR_SUBJECT=default
SONGGUO_ALIYUN_EDU_OCR_OUTPUT_ORICOORD=true
SONGGUO_ALIYUN_EDU_OCR_NEED_ROTATE=true
SONGGUO_ALIYUN_EDU_OCR_HYBRID_TEXT_FALLBACK=false
SONGGUO_ALIYUN_EDU_OCR_HYBRID_TEXT_FALLBACK_MIN_ANSWER_RATE=0.6
SONGGUO_ALIYUN_EDU_OCR_FALLBACK_PROVIDER=none
```

说明：

- `auto` 是多题拍照主入口；目标设计中首选 `PaperStructed`，只在结构化质量不足时通过路由补一次 `PaperCut` 或 `PaperOcr`。
- `max_secondary_actions=1` 用来控制成本，避免一张图触发多次 OCR 调用。
- `hybrid_text_fallback=false` 表示不强制双调用；结构、题框或答案覆盖不足时由 `EducationOcrRouter` 决定是否补调。
- `fallback_provider=none` 适合测试真实 OCR 能力；私测产品可按需打开视觉兜底。
- `subject=default` 先保留，因为前端不要求孩子选学科；后续可由后端学科识别后传 `PrimarySchool_Math / PrimarySchool_Chinese / PrimarySchool_English` 做二次优化。

## 11. 开发拆分

### S1：文档和 raw OCR 评测基线

- 固化本方案。
- 新增 raw OCR 调用脚本，支持同一张图对比 `paper_cut / paper_ocr / paper_structed / oral_calculation / question_ocr / formula`。
- 输出题框数、文本长度、答案覆盖率、耗时、错误码和原始 JSON 路径。

### S2：EducationOcrRouter

- 新增 OCR 能力路由层。
- 默认 `PaperStructed`，按质量条件补 `PaperCut` 或 `PaperOcr`。
- 口算页可显式或自动走 `OralCalculation`。
- 记录 `ocr_plan`、`primary_action`、`secondary_actions`、`reason` 和成本级别。

### S3：PaperStructed 专用解析

- 解析 `part_info`、`subject_list`、`element_list`、`answer_list`。
- 提取题型、题干、选项、答案、坐标和题号。
- 作为整页多题主链路的首选结果；`PaperCut` 只在结构化结果不足时补位。

### S4：统一 item 归一化

- 所有 OCR 输出统一到 `EducationOcrItem`。
- 保证前端永远拿到稳定的 `items + bbox + status`。
- 增加 `source_action`、`ocr_confidence`、`quality_warnings`。

### S5：每题判题和状态机

- 口算题：使用 `OralCalculation` 结果快速判。
- 客观题：规则和结构化答案判。
- 主观题：进入学科 rubric。
- 低置信度题：`pending` 或 `fallback_running`。

### S6：异步复核

- 对少数低置信度题调用 `QuestionOcr / Formula / 视觉模型`。
- 不阻塞整页首屏结果。
- 前端支持单题状态刷新。

### S7：真实照片评测集

- 使用 `zhaopian/` 真实照片建立小数据集。
- 每张图标注题目数、题框、孩子答案、正确/错误。
- 分组统计：口算、计算、应用题、选择、判断、填空、语文、英语、双栏、倾斜、反光、模糊。

## 12. 验收指标

| 指标 | 目标 |
| --- | --- |
| 首屏题框返回 | 普通照片 2-4 秒内返回可用题框和初步状态 |
| 题目数量识别率 | 真实照片集按题号人工标注评估 |
| 题框覆盖率 | 题框能覆盖题目主体，不要求像素级完全一致 |
| 孩子答案抽取率 | 按题统计答案是否绑定到正确题目 |
| 判题准确率 | 按题统计 `correct/wrong/pending` 是否合理 |
| 待确认率 | 不确定题宁可待确认，不能强行错判 |
| OCR 调用成本 | 默认一张图一次 OCR，质量不足时最多追加一次整页 OCR |
| 异步复核比例 | 只处理少数低置信度题，避免变成全量多次调用 |

## 13. 当前代码差距

当前代码已经具备的基础：

- 已接入 `AliyunEduOCRProvider`。
- 已有 `paper_cut / paper_ocr / question_ocr / oral_calculation / formula / paper_structed` action 映射。
- 已有 `bbox` 传到 Learning Submission item 的基础。
- 已有小程序提交复核页和题框叠加基础。
- 已有视觉兜底和每题异步复核方向。

仍需持续补强：

- `PaperStructed` 已有最小解析，但当前默认链路还未完全切到结构化优先，需要后续代码整改。
- OCR 路由已经支持 `auto`，但当前 `auto` 仍偏 `PaperCut`；目标是改成 `PaperStructed` 优先，并用真实样本调优质量阈值和二级 action 选择。
- 题目识别、判题、异步复核的状态已打通到 API 和小程序，仍需要真机体验验证。
- 真实照片评测集还不够，不能只靠模拟图片判断成功率。

## 14. 决策

短期采用：

```text
PaperStructed 主链路
  + PaperCut 题区兜底
  + 条件式 PaperOcr 文本/答案补强
  + OralCalculation 口算快判
  + QuestionOcr / Formula 单题异步复核
  + 学科智能体负责最终陪练和主观题 rubric
```

这条路线和当前“拍照判题 + 错题陪练”产品方向一致。教育 OCR 负责看清楚、切清楚、结构化；松果 AI 负责判清楚、讲清楚、记录清楚。
