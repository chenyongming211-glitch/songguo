# 松果AI v0.1 增强方案：小学数学题目结构化网关与关键点释放状态机

## 1. 方案定位

本文档补充《松果AI PRD v0.1》和《松果AI v0.1 技术实施计划》，用于定义下一阶段的数学答疑核心能力升级。

本方案不再把开发重点放在“为某一道题或某一个题型写规则”，而是建立一套可覆盖小学数学 1-6 年级主要题型的通用教学编排机制：

```text
大模型理解题目
-> 结构化输出解题计划和关键点
-> 规则层校验结构、算术、年级适配和答案泄露风险
-> 状态机按关键点逐步释放提示
-> 孩子一步步尝试
-> 系统判断孩子掌握到哪一步
-> 记录错因、错题、画像和家长反馈
```

核心原则：

```text
大模型负责理解和生成。
规则层负责约束和校验。
状态机负责教学节奏。
松果AI业务库负责学习记录。
```

DeepTutor 或其他 LLM 仍然只是 AI 学习引擎，不直接控制教学状态，不直接决定是否给答案。

## 2. 为什么不能只靠规则题型

小学数学题型覆盖面很广，包括：

```text
数与运算
四则混合运算
单位换算
时间与人民币
图形与几何
统计与概率
分数、小数、百分数
方程和等量关系
一般应用题
行程、工程、年龄、盈亏等高年级应用题
带干扰条件的应用题
中文数字、口语化表达、拍照 OCR 噪声
```

如果用规则穷举所有题型，开发成本高，覆盖速度慢，并且遇到自然语言变化就容易失效。

因此，规则的职责不是替代大模型解题，而是约束大模型输出，防止大模型：

```text
直接给答案
跳过思考步骤
输出不适合年级的讲法
算术不自洽
把最终答案提前写进提示
胡编题目条件
把完整讲解一次性给孩子
```

## 3. 总体架构

新增核心能力：

```text
Math Problem Structuring Gateway
小学数学题目结构化网关
```

推荐调用链路：

```text
小程序输入/拍照
-> Songguo Learning API
-> 输入安全检查
-> OCR / 文本确认
-> MathProblemStructuringGateway
   -> 规则快速通道
   -> LLM/DeepTutor 结构化通道
   -> 结构校验
   -> 算术校验
   -> 答案泄露校验
-> KeyPointTeachingStateMachine
-> 当前关键点提示
-> 小程序展示
```

规则快速通道用于低成本处理高频、确定性强的题目。LLM 结构化通道用于覆盖更广泛的小学题型。两条通道都必须输出统一 Schema。

## 4. 大模型输出要求

大模型不能直接输出给孩子看的完整答案。大模型必须先输出结构化 JSON，由后端审核后再决定释放哪一部分。

### 4.1 ProblemAnalysis Schema

```json
{
  "subject": "math",
  "grade": 3,
  "problem_type": "capacity_round_up",
  "knowledge_points": ["乘法求总数", "除法分组", "有余数进一"],
  "conditions": [
    {
      "id": "class_count",
      "text": "一共有4个班",
      "value": 4,
      "unit": "班"
    },
    {
      "id": "students_per_class",
      "text": "每班32人",
      "value": 32,
      "unit": "人/班"
    },
    {
      "id": "bus_capacity",
      "text": "每辆大巴车限坐45人",
      "value": 45,
      "unit": "人/辆"
    }
  ],
  "target": "至少需要多少辆大巴车",
  "solution_steps": [
    {
      "id": "step_total_people",
      "goal": "先求总人数",
      "expression": "4 × 32",
      "result": "128",
      "explanation_for_backend": "4个班，每班32人，所以总人数是128人。"
    },
    {
      "id": "step_capacity_check",
      "goal": "判断车是否坐得下",
      "expression": "128 ÷ 45",
      "result": "2余38",
      "explanation_for_backend": "2辆车只能坐90人，还剩38人。"
    },
    {
      "id": "step_round_up",
      "goal": "理解有余数要进一",
      "expression": "2 + 1",
      "result": "3",
      "explanation_for_backend": "剩下的人也需要一辆车，所以至少需要3辆。"
    }
  ],
  "final_answer": "3辆",
  "common_misconceptions": [
    {
      "tag": "stopped_at_total_count",
      "description": "只算出总人数就停止"
    },
    {
      "tag": "ignored_remainder_round_up",
      "description": "知道要分车，但忽略余数也需要一辆车"
    },
    {
      "tag": "used_group_count_as_answer",
      "description": "把班级数直接当成车辆数"
    },
    {
      "tag": "copied_capacity",
      "description": "只抄限坐人数，没有理解问题"
    }
  ],
  "key_points": [],
  "confidence": 0.91,
  "source": "llm_structured"
}
```

### 4.2 KeyPoint Schema

大模型必须输出解题关键点，并标注释放时机。

```json
{
  "key_points": [
    {
      "id": "kp_total_people",
      "name": "先求总人数",
      "teaching_goal": "让孩子知道4个班每班32人，要先算总人数",
      "release_stage": "HINT_STEP_1",
      "unlock_condition": "question_started",
      "child_prompt": "先不急着算车。题目说有4个班，每班32人，你先想一想一共有多少人？",
      "expected_child_response": ["128", "128人"],
      "forbidden_content": ["3辆", "最终答案是3辆"],
      "required_before_next": true
    },
    {
      "id": "kp_capacity_check",
      "name": "判断车辆容量",
      "teaching_goal": "让孩子用车辆数乘45判断是否坐得下",
      "release_stage": "HINT_STEP_2",
      "unlock_condition": "child_found_total_people",
      "child_prompt": "你已经算出总人数了。现在想想：2辆车最多能坐多少人？",
      "expected_child_response": ["90", "90人"],
      "forbidden_content": ["3辆"],
      "required_before_next": true
    },
    {
      "id": "kp_round_up",
      "name": "有剩余也要加一辆",
      "teaching_goal": "让孩子理解至少需要时，有余数要进一",
      "release_stage": "HINT_STEP_3",
      "unlock_condition": "child_tried_vehicle_count",
      "child_prompt": "如果还有人没坐上，这些人是不是也需要一辆车？",
      "expected_child_response": ["需要", "还要一辆", "3"],
      "forbidden_content": [],
      "required_before_next": true
    }
  ]
}
```

关键要求：

```text
1. 每个题目必须有 key_points。
2. 每个 key_point 必须说明教学目标。
3. 每个 key_point 必须有 release_stage。
4. 每个 key_point 必须有 child_prompt。
5. child_prompt 是候选提示，不是直接返回内容。
6. 后端必须检查 child_prompt 是否泄露最终答案。
7. 状态机只能释放当前阶段允许的 key_point。
```

## 5. 关键点释放状态机

状态机必须从“提示等级控制”升级为“关键点释放控制”。

### 5.1 状态字段

每个学习会话需要维护：

```text
current_key_point_id
released_key_point_ids
mastered_key_point_ids
blocked_key_point_ids
hint_level
attempt_count
answer_unlocked
last_misconception
current_prompt
```

### 5.2 状态流转

```text
NEW_QUESTION
-> STRUCTURING
-> PLAN_READY
-> HINT_STEP_1
-> WAIT_CHILD_ATTEMPT
-> EVALUATE_ATTEMPT
-> HINT_STEP_2
-> WAIT_CHILD_ATTEMPT
-> EVALUATE_ATTEMPT
-> HINT_STEP_3
-> WAIT_CHILD_ATTEMPT
-> FULL_EXPLANATION_UNLOCKED
-> SIMILAR_PRACTICE
-> SESSION_SUMMARY
```

### 5.3 释放规则

状态机负责决定：

```text
当前能释放哪个关键点
孩子是否掌握当前关键点
是否进入下一个关键点
是否需要退回更简单的提示
是否允许完整讲解
是否生成同类练习
```

硬性规则：

```text
1. 大模型不能直接推进状态机。
2. 大模型不能决定 answer_unlocked=true。
3. 每次最多释放一个关键点。
4. answer_unlocked=false 时不能出现 final_answer。
5. 未满足 unlock_condition 时不能释放后续关键点。
6. 状态机要记录每次关键点释放事件。
```

### 5.4 关键点释放事件

建议新增或扩展 LearningEvent：

```json
{
  "event_type": "key_point.released",
  "session_id": "s_001",
  "child_id": "child_001",
  "payload": {
    "key_point_id": "kp_total_people",
    "release_stage": "HINT_STEP_1",
    "hint_level": 1,
    "prompt": "先不急着算车。题目说有4个班，每班32人，你先想一想一共有多少人？"
  }
}
```

```json
{
  "event_type": "key_point.mastered",
  "session_id": "s_001",
  "child_id": "child_001",
  "payload": {
    "key_point_id": "kp_total_people",
    "child_answer": "128",
    "evidence": "孩子能正确算出总人数"
  }
}
```

## 6. 尝试评价

孩子每次回答后，系统不能只判断整题对错，还要判断孩子掌握了哪个关键点。

### 6.1 AttemptEvaluation Schema

```json
{
  "correct": false,
  "partially_correct": true,
  "matched_key_point_id": "kp_total_people",
  "mastered_key_point_ids": ["kp_total_people"],
  "next_key_point_id": "kp_capacity_check",
  "misconception_tag": "stopped_at_total_count",
  "evidence": "孩子回答128，说明已经算出总人数，但还没有完成分车判断。",
  "next_action": "release_next_key_point"
}
```

### 6.2 典型回答处理

以春游大巴题为例：

```text
孩子答 128
-> 部分正确
-> 标记 kp_total_people 已掌握
-> 错因或卡点：stopped_at_total_count
-> 释放 kp_capacity_check
```

```text
孩子答 2
-> 部分理解分车
-> 卡点：ignored_remainder_round_up
-> 释放 kp_round_up
```

```text
孩子答 3
-> 整题正确
-> 进入 SIMILAR_PRACTICE / SESSION_SUMMARY
```

这能避免把 `128` 这种“第一步正确”误判为普通错误。

## 7. 规则层和校验层

规则层必须校验大模型输出，而不是无条件信任。

### 7.1 校验范围

```text
结构校验：必填字段是否存在
算术校验：表达式和结果是否自洽
答案校验：final_answer 是否由步骤推出
关键点校验：key_points 是否覆盖主要 solution_steps
提示校验：child_prompt 是否提前泄露答案
年级校验：讲法是否适合小学对应年级
安全校验：是否包含不适合儿童的内容
```

### 7.2 校验失败处理

```text
结构缺失：要求模型重试结构化
算术错误：要求模型重试，或退回人工确认
答案泄露：删除/重写 child_prompt
置信度低：只做题目确认，不进入自动讲解
连续失败：进入安全兜底提示
```

## 8. 大模型和成本策略

不是每一句对话都调用大模型。

推荐策略：

```text
题目首次进入时：调用大模型做结构化
孩子每次回答后：优先用规则和 key_point expected responses 判断
规则判断不了：再调用小模型/大模型做 AttemptEvaluation
提示生成：优先使用 key_point.child_prompt 和模板
完整讲解：只有 answer_unlocked=true 后才允许调用模型润色
周报总结：异步批量调用模型
```

这样能保证：

```text
覆盖面由大模型提供
成本由规则和缓存控制
教学节奏由状态机控制
答案泄露由后处理拦截
```

建议环境变量：

```bash
SONGGUO_MATH_STRUCTURING_PROVIDER=deterministic|deeptutor|llm
SONGGUO_MATH_ATTEMPT_EVALUATOR=rules|llm_fallback
SONGGUO_MATH_LLM_FALLBACK=0|1
```

## 9. 小学数学覆盖策略

覆盖小学所有年级的“几乎所有题型”，不等于一次性写完所有规则，而是建立统一结构化能力。

第一层：统一 Schema 覆盖所有题型。

```text
题型
年级
知识点
条件
目标
步骤
关键点
答案
错因
提示计划
同类题参数
```

第二层：大模型提示词用小学数学题型 Taxonomy 约束输出。

```text
数与运算
四则混合运算
应用题
单位换算
时间与人民币
图形与几何
分数/小数/百分数
统计与概率
规律题
方程/等量关系
行程、工程、年龄、盈亏等高年级应用题
```

第三层：逐步增加高频题型规则快通道。

```text

```

规则快通道用于降成本，不作为覆盖面的唯一来源。

## 10. 与现有 v0.1 的关系

当前 v0.1 MVP 已具备：

```text

answer_unlocked 控制
答案泄露检查
错题记录
同类题
家长反馈
```

本方案是在 v0.1 基础上增加：

```text
题目结构化网关
关键点列表
关键点释放时机
步骤级尝试评价
部分正确识别

LLM 结构化 fallback
```

它不是替换现有 v0.1，而是把 v0.1 从“计算题演示闭环”升级为“自然语言小学数学题的受控教学闭环”。

## 12. 验收标准

以春游大巴题为第一条黄金路径：

```text
题目：学校组织三年级学生春游，一共有4个班，每班32人。如果每辆大巴车限坐45人，那么至少需要多少辆大巴车？
```

必须满足：

```text
1. 创建会话后，系统识别 problem_type=capacity_round_up。
2. 首次提示只释放“先求总人数”，不能出现“3辆”。
3. 孩子答 128，系统判定部分正确，并释放“判断车辆容量”关键点。
4. 孩子答 2，系统识别 ignored_remainder_round_up，并提示剩余人数也需要车。
5. 孩子答 3，系统判定整题正确。
6. 系统记录 key_point.released 和 key_point.mastered 事件。
7. 错题本记录具体错因，而不是 unknown_misconception。
8. 家长反馈能说明孩子卡在“有余数进一”或“只算总人数”。
9. 默认不调用大模型生成每一句提示。
10. LLM 输出即使包含最终答案，也不会在解锁前返回给孩子。
```

## 13. 结论

松果AI要覆盖小学数学主要题型，不能靠规则穷举，也不能让大模型自由聊天。

推荐主线是：

```text
大模型结构化题目和关键点
规则校验结构和答案
状态机按关键点逐步释放
泄露检查器阻止提前给答案
业务层记录错因和画像
```

状态机必须明确控制：

```text
让大模型回答出解决问题的关键点。
让每个关键点带有释放时机。
只在合适时机把对应关键点告诉孩子。
```

这套机制是松果AI从“AI答题工具”变成“专属AI教师”的关键底座。
