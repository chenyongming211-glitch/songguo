# 松果AI v0.1 一题一会话 LLM Runner 方案与开发计划

> 2026-05-04 更新：本文档保留为 M6 基础能力方案。M6 负责当前题 messages、Student Context Pack、LearningDeposit 等底座；新的主运行时在 M7 切换为 LangGraph MathMistakeTutorGraph，详见 `songguo/docs/v0.1-langgraph-tutor-agent-plan.md`。

## 1. 方案结论

v0.1 的 AI 学习链路调整为“一题一会话”的 LLM-first 方案：

```text
一名学生开始一道题
-> 创建一个独立 LearningSession
-> 当前题目的完整会话 messages 每轮都可以提交给大模型
-> 大模型负责当题内的讲解、追问、错因判断、同类题生成和总结
-> 松果AI负责长期记忆、数据隔离、答案控制、结构化落库和家长报告
-> 题目完成后关闭当前 LearningSession
```

这里的“完整会话”只指当前这道题从开始到结束的短会话，不包括孩子所有历史聊天记录。

## 2. 核心边界

### 2.1 当前题会话可以完整交给大模型

一题内的上下文通常很短，即使包含：

```text
题目原文
题目识别结果
孩子每一步回答
松鼠博士每一步追问
当前教学规则
当前答案控制状态
```

也远低于现代大模型上下文长度。因此，每次孩子提交回答时，可以把当前题内完整 messages 传给大模型，让模型理解完整教学过程。

### 2.2 长期历史不能全量交给大模型

长期历史仍然由数据库主导，只能以摘要和相关片段形式注入：

```text
最近一周高频错因
最近一周薄弱知识点
最近一次同类题表现
家长设置
短期学习目标
必要的 1-3 条历史证据
```

禁止把所有旧会话、所有错题、所有周报原文无差别塞进 prompt。

原因：

1. 成本和延迟不可控。
2. 旧错因可能污染当前题判断。
3. 难以保证学生数据隔离。
4. 不利于后端做可解释统计和家长报告。

## 3. 新架构

```text
微信小程序
  -> 松果AI后端
    -> SessionContextBuilder
       -> 学生摘要 / 家长设置 / 相关历史证据
       -> 当前题完整 messages
       -> 教学协议和输出 Schema
    -> LLMSessionRunner
       -> 大模型 API
       -> M7 中被 MathMistakeTutorGraph 的 call_tutor_model_node 复用
    -> OutputGuard
       -> 答案泄露检查 / 儿童安全检查 / Schema 校验
    -> LearningDepositService
       -> QuestionRecord / MistakeRecord / PracticeRecord
       -> StudentMemory / DailySummary / WeeklySummary
    -> 小程序展示
```

DeepTutor 在 v0.1 中仍是可选引擎。默认路线通过松果AI后端调用大模型 API；后续 DeepTutor 可以作为 TutorGraph 的工具、教学资产来源、`LLMProvider` 或增强型 `AIEngineProvider` 接入。

## 4. 每次调用大模型的输入

### 4.1 System Prompt

固定教学协议：

```text
你是松果AI的松鼠博士。
你面向小学阶段孩子进行一题一会话陪练。
你不能默认直接给最终答案。
你要先鼓励，再追问，一次只问一个问题。
你必须根据孩子当前回答继续推进。
如果孩子已完成关键步骤，可以逐步释放下一步。
如果 answer_unlocked=false，不能输出最终答案。
你必须返回 JSON，包含 child_message 和 structured_state。
```

### 4.2 Student Context Pack

由数据库动态生成，不是大模型长期记忆：

```json
{
  "child_id": "child_001",
  "grade": 3,
  "recent_week_summary": {
    "weak_points": ["限载进一", "应用题读题"],
    "common_misconceptions": ["有余数但没有进一"],
    "hint_dependency": "medium"
  },
  "parent_settings": {
    "answer_mode": "strict_guided",
    "focus": ["应用题先找条件"]
  },
  "short_term_goal": "先训练读题、找条件、判断问题"
}
```

### 4.3 Current Problem Session Messages

当前题内完整 messages 可以全部传入：

```json
[
  {
    "role": "user",
    "content": "学校组织三年级去植物园，有6个班，每班27人。每辆大巴车最多坐40人，至少需要多少辆大巴车？"
  },
  {
    "role": "assistant",
    "content": "先不急着回答几辆车。6个班，每班27人，一共有多少人？"
  },
  {
    "role": "user",
    "content": "162"
  }
]
```

## 5. 大模型输出 Schema

大模型不能只返回自然语言。v0.1 要求返回结构化 JSON：

```json
{
  "child_message": "你已经知道一共有162人。每辆最多坐40人，先想想4辆最多能坐多少人？还剩人吗？",
  "structured_state": {
    "phase": "WAIT_CHILD_ATTEMPT",
    "answer_unlocked": false,
    "current_key_point": "判断车辆容量",
    "mastered_key_points": ["先求总人数"],
    "main_misconception": null,
    "hint_dependency_delta": 1,
    "should_end_session": false
  },
  "learning_deposit_delta": {
    "knowledge_point": "限载进一应用题",
    "question_type": "capacity_round_up",
    "evidence": "孩子已能算出总人数162，但还需要判断限载后是否有剩余。",
    "need_review": true
  },
  "practice_items": []
}
```

题目完成时：

```json
{
  "child_message": "你已经找到方法了。我们再练3道同类题，确认真的掌握。",
  "structured_state": {
    "phase": "SIMILAR_PRACTICE",
    "answer_unlocked": true,
    "should_end_session": true
  },
  "learning_deposit_delta": {
    "is_correct": true,
    "main_misconception": "有余数时需要进一",
    "hint_dependency": "medium",
    "parent_summary": "孩子能算出总人数，但需要继续巩固限载场景中有剩余也要再加一辆。"
  },
  "practice_items": [
    {
      "question": "三年级去参观科技馆，有5个班，每班28人。每辆车最多坐40人，至少需要几辆车？",
      "answer": "4辆",
      "knowledge_point": "capacity_round_up",
      "difficulty": 1
    }
  ]
}
```

## 6. 后端兜底规则

即使当前题完整交给大模型，后端仍必须控制以下事项：

1. `answer_unlocked=false` 时，输出不得泄露最终答案。
2. 大模型 JSON 解析失败时，使用本地安全 fallback。
3. 大模型返回的 `child_id`、`session_id`、`grade` 等身份字段不可信，必须以后端会话为准。
4. 大模型建议的错因可以进入候选，但落库前要映射到松果AI标准错因标签。
5. 大模型生成的同类题数量必须限制在 1-3 道。
6. 每次模型调用必须记录 provider、model、latency、token_estimate、status。
7. 会话结束后必须生成 LearningDeposit，不能只保存聊天记录。

## 7. 学习档案分层

学生学习档案采用数据库分层，而不是 Markdown 文档：

```text
原始层：LearningSession / LearningMessage / LearningEvent
题目层：QuestionRecord / MistakeRecord / PracticeRecord
日层：DailyLearningSummary
周层：WeeklyLearningSummary
月层：MonthlyLearningSummary
画像层：StudentMemory / StudentProfileSeed
家长层：ParentSummary / WeeklyReportDraft
```

### 7.1 每天记录

每天自动沉淀：

```text
当天错题
当天纠正过的知识点
当天提示依赖情况
当天新增或复发错因
当天完成的同类题
```

### 7.2 每周归纳

每周归纳：

```text
过去七天反复出现的错因
频繁卡住的知识点
提示依赖趋势
改善明显的能力点
下周建议练习方向
家长可执行辅导建议
```

### 7.3 每月归纳

每月归纳：

```text
学习趋势
持续薄弱点
明显改善点
复习完成情况
下月重点目标
```

## 8. 与当前 Runtime Kernel 的关系

当前已有 Runtime Kernel、结构化数学网关和 Teaching Asset Library 不删除，但定位调整：

```text
过渡期旧实现：规则/状态机偏重，模型辅助结构化。
新定位：大模型主导当前题自然教学，Runtime Kernel 做安全兜底和结构化校验。
```

M7 后短期保留三种模式：

```text
SONGGUO_AGENT_RUNTIME=langgraph  # MathMistakeTutorGraph 主运行时
SONGGUO_AGENT_RUNTIME=llm        # M6 一题一会话 Runner 过渡模式
SONGGUO_AGENT_RUNTIME=kernel     # Runtime Kernel 兜底模式
```

MVP 推荐逐步切到 `langgraph`，但保留 `llm` 和 `kernel` 作为模型失败、成本控制和高频题的 fallback。

目标：新增一题一会话运行器。

文件范围：

```text

songguo/backend/services/learning/session_context.py
```

```text

3. 模型输出必须解析为 child_message + structured_state + learning_deposit_delta。
4. JSON 解析失败时返回安全 fallback。
```

### M6-2：新增当前题 LearningMessage 持久化

目标：当前题完整 messages 可恢复、可提交给大模型。

文件范围：

```text
songguo/backend/services/learning/models.py
songguo/backend/services/learning/store.py
```

验收：

```text
1. 每次孩子输入和松鼠博士回复都写入 LearningMessage。
2. resume session 时能恢复当前题 messages。
3. 会话结束后 messages 保留为原始证据，不直接作为长期记忆注入下一题。
```

### M6-3：新增 Student Context Pack Builder

目标：为每次新题动态提取学生摘要和相关历史。

文件范围：

```text

songguo/backend/services/learning/memory_profile.py
```

验收：

```text

2. 不注入其他 child_id 的任何数据。
```

## 11. 最小演示标准

用一道全新的三年级应用题演示：

```text
1. 创建新 LearningSession。
2. 第一轮大模型不直接给最终答案。
3. 孩子回答中间步骤后，大模型基于当前题完整 messages 继续追问。
4. 孩子答对后生成 1-3 道同类题。
5. 会话结束后生成 LearningDeposit。
6. 家长页看到本次卡点、错因、下一步建议。
7. 新开下一题时，只注入摘要和相关历史，不注入上一题完整聊天。
```

## 12. 结论

松果AI v0.1 的新主线是：

```text
当前题内：完整会话交给大模型，获得自然、连续、个性化的教学体验。
题目结束后：结构化沉淀到数据库，形成学生长期学习档案。
下一题开始：只注入摘要和相关历史证据，避免长期上下文污染。
```

M6 的价值是把“当前题完整上下文”和“题后结构化沉淀”打通。M7 在此基础上引入 LangGraph MathMistakeTutorGraph，先把数学错题对话做成真正像 AI 老师的自然流程，而不是固定步骤状态机。
